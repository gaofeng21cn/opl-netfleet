# NetFleet UI 设计合同

本文是 NetFleet 当前视觉语言、页面组织和交互呈现的唯一详细设计合同。
[当前架构](../architecture/overview.md)继续负责产品对象、状态 owner、RPC、动作和安全边界；本文不重复或改写这些运行合同。

## 产品气质

NetFleet 提供 OpenWrt 网络运维界面和 macOS 本机客户端。页面应安静、清晰、紧凑，优先支持扫描、比较和重复操作，不采用营销页、移动应用或装饰性仪表盘的表达方式。

界面遵循以下原则：

- 信息层级先于装饰：页面标题、来源状态、主要内容、辅助诊断和操作反馈从上到下稳定排列；
- 状态颜色只表达需要辨认的状态：绿色只用于健康指示和明确成功反馈，普通运行值、当前选择与合格延迟使用主题强调色；
- 主题色负责选择和动作：导航选中、主按钮、输入焦点和步骤进度具体主题值由平台宿主提供；
- 同类信息使用同一容器：指标、表格、配置行、恢复说明和日志分别使用稳定的组件形态；
- 桌面优先：主要布局针对常见电脑宽度设计，窄屏只保证内容可达、文字不重叠、表格可横向滚动。

布局采用紧凑的网络管理工作台：正常运行与读取来源用单行信息条表达，细分隔线组织页面，
不使用浮动分区卡片。主导航按用户任务组织，颜色跟随宿主主题，不复制其他产品的
物理拓扑、营销组件或没有证据的历史图。短交互使用不超过 160ms 的颜色过渡，并尊重减少动态效果设置。

机场与地区支持本地搜索、按名称/最近最优/平均最优排序及当前使用筛选；排序只改变显示，
不写策略或重新测速。点击机场名称打开同页右侧详情，列表保留比较上下文；窄屏改为列表下方详情，
不遮挡表格。详情可关闭，Escape 返回列表焦点；切换机场直接替换内容。运行质量、订阅配额和更新记录
按主题分组，原有字段不丢失。流量条仅在设备返回可靠总额及剩余值时显示，不推算订阅周期或历史趋势。
对象操作跟随页面：机场更新在机场页，选优在概览/出口/地区，启停在概览；事件、配置和组件不重复放业务写入按钮。

## 跨平台交互一致性

OpenWrt、macOS 与本地参考页使用同一套业务词汇和任务顺序：概览、出口、机场、地区、配置、诊断。组件更新和网络接入按宿主真实能力呈现。平台布局可适配，页面职责、对象命名、列表筛选、详情展开和动作含义必须一致。

地区选择从出口的“指定地区”或地区行的“改用此地区”进入同一个确认流程：选择出口、查看当前路径、选择保持地区、说明作用范围、确认切换。候选必须来自本次状态中的授权地区；不可操作时给出原因。“重新选优”遵守健康地区切换门槛；后台已暂停时入口显示“恢复自动选优”，并说明解除各自动出口手动保持的整轮影响。不能把全局自动选优恢复解释为单个出口操作。

配置采用草稿、校验、变更预览、保存、运行生效的相同阶段。Mihomo 高级设置位于网络配置页的可折叠次级区，不抢占网络模式和 DNS 主区；每项显示配置来源、配置值与运行值，并提供恢复继承。专家 JSON 只编辑同一份草稿，省略字段保持原草稿，`null` 表示继承；无效 JSON 在校验和应用前阻止请求。按钮必须表达后端真实能力；保存、编译、运行应用分别显示，不用相同按钮文案掩盖不同生效范围。请求成功后重新读取 owner 状态，回读失败显示未确认，禁止以提交成功替代生效。确认框支持取消、Escape 和焦点返回；键盘焦点保持在对话框内。

## 地区选择与操作层级

概览用于扫描当前运行与统计差异，摘要跳转使用主题色文字链接，不能呈现为灰色禁用按钮。
出口页是选择控制的主要入口，每张出口卡片提供“指定地区”；地区页提供相同入口并预选
该地区，随后选择具有该地区授权的出口。确认区显示当前路径、目标地区和保持范围；
只读、缓存状态、操作中或无已编译授权地区时禁用提交，并解释原因。
手动保持状态紧邻当前路径，并提供“恢复自动选优”。后台暂停的作用范围及重新应用配置
会重新决定选择在确认前说明，节点级选择仍交给核心。

“重新选优”保留当前健康地区的切换门槛，“指定地区”表达用户明确意图，两者不能共用
含糊标签。地区比较的说明区同时展示当前使用和选择方式；“本轮测速”“最近测量最快”
与“历史平均最低”区分测量口径。行内操作保持紧凑，主操作可见，无需滚到页底。
源信息保持辅助层级，正常读取不占用一整张指标卡；错误、缓存与只读仍明确可见。出口摘要突出地区与机场，完整节点链路、业务绑定和恢复规则归可展开详情。地区行标明正在使用它的出口，选择说明使用设备记录的原因，不按表格排名推导切换建议。

## HTTPS 兼容详情

HTTPS 插件通过自身页面声明提供唯一管理页，组件列表的“配置”按钮进入同一页面，
使用原生复选框、表格和编辑对话框。
页头保留返回组件列表、功能说明、总开关与实际状态，内部按“规则 / 设备与信任 / 诊断”
分栏。安装版本归组件列表，包管理入口归诊断；配置页不重复提供模块表单。总开关显示用户意图，运行
标签显示 owner 的实际接管状态；开启但没有接管时显示“已开启，当前旁路”。规则与
设备编辑独立提交并回读，不显示基础配置的全局应用按钮。系统信任和 App、CLI、图片
实际验证分别呈现。首页和全局事件页不加载 HTTPS 控件与资源。
再次打开立即显示上次规则和设备摘要，页尾显示“上次读取时间 / 正在刷新 / 刷新失败”，
旧摘要不提供写入权限。首次无摘要时先呈现页头、分栏和读取反馈，不显示伪造的关闭状态。
普通状态刷新不清空内容，只有选中的分栏生成内容；切换分栏在本地完成。正常空闲时无
周期请求，启停、恢复和排空只做有界状态跟进。刷新后保留焦点及展开内容。
规则状态同时表达总开关与规则状态，最近协议单列次要文字；地址和 CA 指纹折叠展示。
设备来源管理放在“高级：设备地址来源”，避免把可选外部控制器配置当成基本接入步骤。
面板只使用宿主主题色；诊断导出与软件包管理归诊断分栏，主要界面保留总开关、规则和设备。
诊断展示后台已有的本地转发链、目标恢复和事件记录；刷新状态不冒充新发起的连接测试。

## 宿主边界与颜色

共同合同统一对象、动作、状态解释、页面职责和视觉 token；布局、控件密度、系统主题、
菜单快捷键与授权流程按平台适配。宿主只承接系统集成，业务状态和草稿不由原生菜单另存。
具体渲染机制与平台专属交互见[OpenWrt](../platform/openwrt.md#界面渲染与主题)和
[macOS](../platform/macos.md#桌面布局与系统交互)。

`OPL` 标识可以保留品牌红；健康指示与成功用绿色，注意用橙色，失败和破坏性动作用红色。
正常运行、当前选择和导航使用宿主主题强调色，不以大面积绿色代表产品身份；对象身份
不获得专属装饰色。页面中性底色、细分隔线和清晰层次保持一致。

## 尺度与排版

下列基准用于共享网页参考面；平台可调整字体、密度和圆角，保留信息层级与间距序列，
宿主尺寸差异不改变动作名称和操作顺序。

- 页面最大内容宽度为 `1440px`；常规内容使用 `15px` 基准字号和约 `1.5` 行高；
- 页面标题为 `24-28px`，分区标题为 `17-21px`，表格正文不低于 `13px`；
- 控件高度使用 `38-46px`，确保桌面鼠标操作稳定且文字不拥挤；
- 间距以 `4 / 8 / 12 / 16 / 20 / 24px` 为基础序列；
- 容器圆角统一为 `6px`，不用大圆角胶囊或层层嵌套卡片；
- 字距固定为 `0`，不随视口缩放字号。

## 页面骨架

“插件与更新”独立于业务配置，位于配置与事件诊断之间，以 NetFleet、Mihomo 代理核心、
实时面板及管理界面分别展示当前版本、更新结果和可执行操作；功能插件与
可选模块归“功能插件”分栏，版本更新归“基础组件”分栏，不把包名混入更新状态列。界面与 runtime 可独立发行，版本号
不同不构成异常；设备提供的更新事务仍决定哪些包一起更新。Mihomo 以实际运行版本为主，安装记录
放在次要位置；忽略版本前缀和包修订号后仍不一致时明确提示，不把包更新冒充运行核心升级。
不适用字段不呈现；未检查、检查失败、未安装、版本未记录和版本不一致分别表达。
页首提供状态刷新与检查更新，实际安装按组件确认；不使用常驻教学段落占据主区域。
可选模块显示安装版本与“可配置”，不把模块接口兼容误称为已经启用；启用及实际运行状态
归模块详情页。暂不由组件事务更新的可选包明确指向平台对应的管理入口，不留无解释的空操作。
面板版本显示设备 owner 从安装记录或实际资源识别出的版本；文件存在但无法识别版本时，
显示“版本未记录”并保留“已安装，可使用”，不把候选版本当成当前版本。

页面打开仅读取设备缓存。页首统一“检查更新”按顺序查询面板发行源和软件包源，分别保留
检查时间与失败原因；不自动安装，也不因一个来源失败掩盖另一个结果。安装或更新仍逐项
确认，只有存在可执行候选才显示操作，不常驻无意义的灰色更新按钮。刷新设备状态使用
单一图标入口；Feed、架构和包明细归技术详情，依赖正常时折叠，缺失时展开。
Zashboard 保持标题工具区的独立入口，组件行也可打开完整面板；外部管理资源明确标注管理者，不把静态资源伪装成软件包。

订阅、选优与软件更新展示设备真实阶段、当前对象、已处理/总数及耗时，不用估算百分比。
操作进行中允许收起弹窗，机场、出口或组件页保留对应进度；短暂连接中断标为等待设备回读，执行失败、
正在恢复和恢复完成分别显示。只有操作进行中才轮询进度，普通页面的读取周期由平台机制决定，视觉调整不额外增加轮询。
所有已结束操作收为紧凑的行内结果，显示对象、结果、设备记录的完成时间和固定耗时，
失败与恢复结果分别保留。完成时间缺失时只显示已记录的更新时间，不用浏览器当前时间
假造完成时间或让终态耗时继续增长。结果带可访问的关闭按钮，不覆盖页面内容。
关闭只影响本浏览器会话内该操作结果的展示，不取消后台操作、不清除设备记录、不改变
写入权限；重绘、刷新和切换页面不重复弹回同一结果，新操作及恢复结果变化重新显示。
只允许保存按目标隔离的操作标识与状态，不保存订阅、错误正文或凭据。运行中的进度和
当前持续故障不能由关闭结果隐藏；更新源的当前检查状态和诊断详情仍可查看，不重复铺开
同一失败文案。普通通知使用宿主关闭能力并显示收到反馈的时间。
Zashboard 资源检查与更新使用有界同步请求，显示进行中、结果或失败原因，不伪造下载
百分比或尚不存在的逐阶段操作记录。

订阅更新触发的测速按操作父子身份合并为同一条进度，阶段名称区分订阅处理、测速选优与运行确认；独立测速使用自己的进度条。

所有页面保持“页面标题与页面级操作 -> 当前页面内容 -> 数据来源与新鲜度”的顺序。数据来源只解释当前 UI 的读取状态，统一放在内容之后并紧邻刷新操作，不抢占首屏的业务信息层级。

页面标题右侧持续显示设备 owner 返回的 `NetFleet v<version> · <source commit 短号>`，用于确认运行软件身份；界面包版本在组件页独立显示，静态资源缓存遵循双宿主边界。版本或部署身份缺失时明确显示“版本未提供”，不得由浏览器根据文件时间或缓存内容猜测。

- 概览：运行状态、出口摘要和资源入口，面向快速扫描与操作；OpenWrt 保留机场/地区/最近决策摘要，桌面首屏采用下述紧凑组合；不复制出口页的全部诊断字段；
- 出口：每个 capability 先显示当前路径、延迟、健康和选择方式；卡片标题和说明保持紧凑，保持标题与说明对齐；绑定的业务分类按“默认走此出口”和“默认直连、可临时切换”分开展示，并以可换行的紧凑分组呈现，不暴露“接管的原始策略组”等实现术语；运行时故障退路放在卡片展开详情，选优口径和退出恢复另列；
- 策略与节点：基础配置先说明当前策略来源与节点来源的独立职责，内置策略显示海外加速和 AI 出口两个业务入口；自定义 Profile 导入放在展开项。切换已有策略要说明会替换来源、绑定和出口定义，保留资源与恢复配置；验证失败不能显示切换成功。表单标签、说明、控件与底部操作使用一致的列对齐和间距，次级操作不挤压主要内容。
- 机场与地区：以表格比较为主，表头、选中项、延迟、样本和空状态保持一致；机场页顶部保留自动更新、周期、最近执行、正常订阅数和最近结果的全局摘要，并提供紧凑的“管理订阅”入口：本产品管理的来源在本界面编辑，外部管理的来源转到其唯一管理入口；主体以机场为唯一行对象，把订阅状态与运行质量汇总到同一行，不再并列“订阅缓存”和“机场”两张重复表；机场“可用资源”的第一行是地区覆盖，第二行是 Mihomo 已加载节点的“可用/总数”，当原始订阅条目更多时同处补充“订阅 N 条”，候选地区组不能显示成节点；
- 配置：使用左侧分类、右侧内容和底部操作反馈，分类依次为“基础接入 / 机场 / 地区映射 / 出口策略 / 业务规则 / 自动运行 / 安全与恢复 / 网络接入 / 配置文件与备份”。分类按“运行策略 / 设备与文件”分组，并明确草稿提交范围；策略区保留“校验与变更”和随运行状态变化的主操作，支持运行中应用时为“应用更改”，其余情况下为“保存配置”并提供独立启用入口。策略编辑只从当前后端返回的订阅、已识别地区和策略基础的组中选择，新增/删除对象均使用明确的行级动作，结构化编辑不提供任意 policy JSON 或正则输入；平台可提供经同一 validator 校验的独立高级入口。网络接入与配置文件/备份使用独立读取、校验和确认操作，不受策略草稿的底部保存按钮控制；
- 诊断：页内按“选路记录 / 网站诊断 / 核心与日志”分栏，默认展示 NetFleet 已确认完成的选路事件；网站连接和核心维护状态进入对应分栏时按需读取；诊断状态随后只用指标组展示设备控制、事件存储、决策事件和当前连接，原始日志的保留口径使用独立辅助说明，不与实时状态伪装成同类指标。核心维护区提供确认后的重启、重载，以及按需读取的有界脱敏启动日志，核心控制接口不可用时仍能排查。当前活动连接只保留为默认折叠的辅助快照，详细规则命中链、流量和实时代理组观察交给 Zashboard。事件表和日志保持高密度，分页与刷新不遮挡内容，日志使用等宽字体和独立滚动区；不能把瞬时连接快照累计成持久规则频数。

## 高级实时观察面

概览首屏优先显示运行状态与出口摘要。网络运行模式默认以紧凑的当前模式和“切换运行模式”入口呈现，展开后显示三项等宽单选卡片，包含模式名称、
作用说明和“当前运行”标记；草稿选中样式与当前运行标记独立，底部显示待切换状态和
“切换模式”按钮。窄屏纵向排列，统一沿用概览卡片的边框、圆角和间距。选中项和状态名称来自
`status.operating_mode`，含义以[运行模式](../architecture/runtime-and-recovery.md#用户运行模式)为准。
切换中禁止重复提交；未知状态不预选正常模式，失败后显示重新读取的当前模式。

网站诊断紧接选路事件，以目标输入、四项接入状态、真实连接命中与下一步组成一个不嵌套
卡片的区块。刷新只读设备证据，查询只筛选内存快照；展示读取时间及截断限制，不用
“未捕获连接”表示网站故障，不把监听就绪写成目标解析成功。高级协议诊断仍进入所属模块。
配置的变更预览区分新增、移除和修改对象；网络接入确认列出变化分类及重启影响，不回显
密码。设备操作返回无变化时明确未重载；执行成功后的读取失败属于状态待确认，不显示
执行失败，也不建议重复应用。

产品主导航依次为“概览 / 出口 / 机场 / 地区 / 配置 / 插件与更新 / 诊断”。插件与更新按“功能插件 / 基础组件”分栏；插件的配置与运行管理从同一对象进入。扩展页面按插件和实例组织，不增加主导航。未安装产品界面时，宿主仍提供插件目录。页面地址记录稳定页面标识，支持收藏、刷新恢复与前进后退；地址不保存配置、凭据或草稿。Zashboard 是外部完整工具，在页面标题右侧单列“Zashboard ↗”，不插入内部标签页。点击后使用上游接入页校验设备当前连接参数并进入完整页面，不嵌入 iframe、不增加 NetFleet 中转页，也不复制概览、机场或地区摘要。“诊断”中的有限连接投影不冒充完整 Mihomo dashboard。

独立面板的入口必须来自当前平台的真实可用性；不可用时禁用并解释原因。有限连接
投影不能冒充完整面板，面板的临时运行操作也不能替代 NetFleet 的持久配置与恢复 owner。

## 组件规则

策略基础使用下拉框，选项仅来自设备返回的可用策略配置，不在前端固定机场或配置名单。
设备访问规则中，已保存且不限制地址的规则明确显示“其余设备（默认规则）”及匹配范围，
不显示三个空地址框冒充未填写的设备。启用、代理和 DNS 接管仍表示真实配置；新增设备规则
默认停用并插入默认规则之前，保留前序特例优先的匹配顺序，不因展示调整改变已保存的接管范围。

订阅制机场的剩余流量下可显示“每月 N 日重置”，提示来源为手动设置；未设置时不增加空态或警告，买断制不显示。原生订阅编辑提供“每月流量重置日”下拉框（未设置、1–31 日），支持修改与清空；它保存即生效，不与修改订阅地址后的“待更新”混淆，不显示没有依据的倒计时。

- 导航：选中项使用主题强调色、浅背景和 3px 指示线；hover 只改变浅背景；
- 指标组：同一外框内使用分隔线，不为每个指标增加独立卡片；五项且内容简短的同类运行口径在宽屏保持单行，中等宽度按三项和两项等宽铺满，不能形成四项加一个孤立单元；不同语义的辅助说明不硬塞进指标组；
- 表格：浅色表头、稳定行高、细分隔线和轻量 hover；选中行使用主题浅背景；
- 机场详情：默认表保留机场定位、可用资源、本轮测速、订阅状态、配额和到期时间；历史最近、历史平均及样本次数归详情。列的隐藏按语义标识同时处理表头与数据，不使用位置序号；宽度不足时详情移至列表下方，表格滚动仅限自身区域；稳定订阅标识、缓存版本、最近尝试、订阅更新时间和最后测量归右侧详情，首次尚未运行 SubscriptionOwner 时显示“尚未执行”。订阅 owner 与运行状态 owner 在后端保持分离，由 status 的明确引用聚合，浏览器不得按机场显示名猜测关系；来源编辑通过独立管理弹窗，不在状态表中暴露地址和凭据；
- 结构编辑：新增机场只能选择当前后端尚未接管的订阅；新增地区只能选择该机场 cache 已识别的地区；新增出口能力需要稳定 ID、显示名和恰好一个入口组；业务组绑定只能选择当前策略基础已有组。业务规则选择域名后缀或 IPv4/IPv6 CIDR，目标为已有出口或直连；域名不含协议、路径或端口，CIDR 必须为合法网段。删除动作必须在本地草稿中同步清理引用，并在“校验与变更”中逐项展示，真正写入仍由配置 owner 校验与确认；
- 状态块：左边界颜色可以表达成功、警告或失败，正文仍保持正常文本色；
- 概览关注区：使用轻背景和警告色左边线，标题与首条提示保持相同行高、顶部对齐；多条提示逐行排列，清除标题和列表的主题默认间距，不复用主题的大面积告警背景；
- 表单：标签和解释在左，控件在右；窄屏才改为上下排列；只读值与可编辑输入必须可区分；
- 配置密度：依据内容区实际宽度收缩分类栏，空间不足时分类横排；表单标签列与控件列统一对齐，控件可收缩。机场名称与资源合为一列，地区名称与覆盖合为一列，单元格内机场选项逐行排列，不在窄列中再次分栏。网络规则按地址、行为与顺序组织，地址框有可见标签；表格内按钮保持成组，新增区域与现有行分开；
- 订阅管理：来源秘密只在经认证的必要编辑面使用，不写入浏览器持久缓存；表单有独立作用域，列宽可收缩。具体可编辑字段和外部管理跳转由平台能力决定；
- 网络接入：只显示已实现并验证的接入方式和受控字段，已保存密码仅显示配置状态；系统网络接入与增强业务分别呈现，安装、授权、核心运行和接管生效不能相互替代；
- 配置文件与备份：列表区分文件引用和可编辑状态，提供导入、下载、受控 JSON/YAML 编辑与删除；使用中的配置不允许直接覆盖或删除。备份导出与恢复是独立确认操作，明确提示包含私有凭据，不把正文放入普通状态缓存；参考界面的私有内容权限由宿主能力限定；
- 操作：主操作使用主题色，普通操作保持中性，破坏性操作使用危险色；同区块内的次级外部跳转使用紧凑文字链接和外部标记，不与页面级操作竞争；禁用态必须同时有视觉和原生 `disabled`；
- 焦点：键盘焦点使用主题色轮廓，不依赖颜色变化之外的隐式反馈；
- 空状态与错误：解释当前事实和下一步，不伪造零值，不使用大面积插画。

表格中的未知信息按对象解释：节点清单暂不可读、机场未返回用量、机场未返回到期时间，
不把所有缺值写成“未提供”。零有效样本合并延迟区为一条“暂无有效测量”；一次测量显示
“仅 1 次测量”，两次起显示平均。地区表把样本次数和最近有效测量时间收入“历史测量”展开内容，
不再并列多个空时间和空平均。表头说明资源为当前可用/已加载，主表延迟为最近一次有效测量、详情历史为每轮最快的有效样本，
库存健康不能暗示测速成功。

未配置时展示本平台的真实接入入口，分别说明将保存配置还是启用网络；预检失败提供
可行动原因，不伪造概览零值，不因尚无 policy 导致整页错误。发现与候选生成由 owner 完成。

## 性能与实现约束

视觉统一不得增加设备 RPC、自动轮询、后台进程或运行状态。空闲请求数、status/events 读取次数和 mutation owner 均由[公开接口与 UI](../architecture/interfaces.md)约束。

网络配置、文件列表和核心日志按进入对应分区或显式刷新读取，不并入每次 status。
预览与生产的权限边界由平台宿主决定；具体管理与恢复边界见[独立管理](../architecture/management.md)。

CSS 使用 scoped token 和现有 DOM，不引入 JavaScript 主题计算。配置草稿可以继续在用户编辑时重绘当前原生 DOM；当前数据规模不需要虚拟列表。只有实际出现数百到上千可见行并取得浏览器性能证据后，才考虑局部更新或虚拟化。

## 可访问与窄屏底线

交互元素保留语义化 button、label、table 和原生 disabled 状态。文本与背景需保持可读对比度；状态不能只靠颜色表达。电脑端是主要验收面，`700-760px` 以下只要求导航可达、操作不重叠、内容不裁切、表格可横向滚动，不为移动端重排或删减业务信息。

测速单元格先显示延迟或明确空态，再显示成功数量和主要限制；采样时间始终可见。逐项结果用原生可键盘展开的详情呈现，包含机场、地区、流量状态和独立测速原因。默认折叠避免长诊断挤占表格；成功与异常同时存在时两者都保留。

### 桌面概览的信息密度

桌面概览是操作起点：首屏依次显示实际连接状态与启停、当前流量接入及切换、启用的业务出口及地区操作，底部只保留机场/地区资源数量和诊断入口。常规双出口在最小窗口内容区 860 × 580 内可见，无需滚动到页面末尾才能操作。状态与主要按钮并排，窗口缩窄时保持紧凑横排；不通过缩小正文、裁切重要内容或锁死滚动来满足首屏。

接入方式以紧凑选择控件和显式应用动作呈现；说明按当前选择显示，管理员授权和系统接管确认沿用平台流程。原生配置模式置于按需打开的选项，历史最快、均值、节点链路和事件详情归机场、地区、出口、诊断页面。出口摘要直接提供地区选择入口；概览和出口详情均不把停止前的健康状态当作当前结果，停用核心时显示未运行且不展示历史测量，保留查看配置入口。主动停止是正常状态；只有运行意图与事实不一致、网络恢复未确认、配置失败或资源耗尽时提示用户处理。

概览不重复长说明，操作进度和结果紧邻当前页面，数据证据集中在诊断页；页面滚动承载超出常规数量的自定义出口及长错误，不能隐藏它们。其他表单和列表保持同一字号、控件高度与间距系统。
