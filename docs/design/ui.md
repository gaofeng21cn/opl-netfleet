# NetFleet UI 设计合同

本文是 NetFleet 当前视觉语言、页面组织和交互呈现的唯一详细设计合同。
[当前架构](../architecture/overview.md)继续负责产品对象、状态 owner、RPC、动作和安全边界；本文不重复或改写这些运行合同。

## 产品气质

NetFleet 是面向电脑使用的 OpenWrt 网络运维界面。页面应安静、清晰、紧凑，优先支持扫描、比较和重复操作，不采用营销页、移动应用或装饰性仪表盘的表达方式。

界面遵循以下原则：

- 信息层级先于装饰：页面标题、来源状态、主要内容、辅助诊断和操作反馈从上到下稳定排列；
- 状态颜色只表达需要辨认的状态：绿色只用于健康指示和明确成功反馈，普通运行值、当前选择与合格延迟使用主题强调色；
- 主题色负责选择和动作：导航选中、主按钮、输入焦点和步骤进度跟随当前 LuCI 主题；
- 同类信息使用同一容器：指标、表格、配置行、恢复说明和日志分别使用稳定的组件形态；
- 桌面优先：主要布局针对常见电脑宽度设计，窄屏只保证内容可达、文字不重叠、表格可横向滚动。

## 双宿主边界

“配置 → HTTPS 兼容”使用原生复选框、表格和编辑对话框。总开关显示用户意图，运行
标签显示 owner 的实际接管状态；开启但没有接管时显示“已开启，当前旁路”。规则与
设备编辑独立提交并回读，不显示基础配置的全局应用按钮。系统信任和 App、CLI、图片
实际验证分别呈现。首页不显示 HTTPS 兼容摘要；事件页保留摘要及管理入口。

本机 React/Vite 页面用于快速评估信息、交互和视觉节奏；设备端原生 LuCI 页面是唯一生产部署实现。两者共享页面名称、可见文案、状态语义、密度和视觉 token，不共享组件代码，也不要求逐像素一致。

生产 LuCI 不加载 React、组件库、远程字体或额外运行时。视觉统一只能通过原生 `view.extend`、`E()` 和 scoped CSS 完成。

## 颜色与主题

设备端颜色从 LuCI 主题变量投影到 NetFleet token。优先级如下：

| 用途 | NetFleet token | LuCI 来源或默认值 |
| --- | --- | --- |
| 选择、焦点、主操作 | `--nf-accent` | `--primary` -> `--primary-color-high` -> `#5e72e4` |
| 浅强调背景 | `--nf-accent-soft` | `--primary-color-low` -> `rgba(94, 114, 228, 0.10)` |
| 正文 | `--nf-text` | `--text-color-high` -> `#202124` |
| 辅助文字 | `--nf-muted` | `--text-color-medium` -> `#5f6368` |
| 页面与容器背景 | `--nf-page` / `--nf-surface` | LuCI background token -> 中性灰 / 白 |
| 边界 | `--nf-border` | `--border-color-medium` -> 中性灰 |

`OPL` 标识可以保留品牌红；健康指示和明确校验成功使用绿色，注意使用橙色，失败和破坏性动作使用红色。正常运行、已启用、可读取、当前使用和合格延迟是主题层级，不用绿色铺满页面。任何地区、机场、出口或导航项不得因为业务身份获得专属装饰色。

## 尺度与排版

- 页面最大内容宽度为 `1440px`；常规内容使用 `15px` 基准字号和约 `1.5` 行高；
- 页面标题为 `24-28px`，分区标题为 `17-21px`，表格正文不低于 `13px`；
- 控件高度使用 `38-46px`，确保桌面鼠标操作稳定且文字不拥挤；
- 间距以 `4 / 8 / 12 / 16 / 20 / 24px` 为基础序列；
- 容器圆角统一为 `6px`，不用大圆角胶囊或层层嵌套卡片；
- 字距固定为 `0`，不随视口缩放字号。

## 页面骨架

“组件与更新”独立于业务配置，位于配置与事件诊断之间，以 NetFleet、Mihomo 代理核心、
Zashboard 实时面板三个对象展示当前版本与状态、更新结果和可执行操作。LuCI 包随 NetFleet
管理，其版本放在展开详情；两包版本不一致时才提醒。Mihomo 以实际运行版本为主，安装记录
放在次要位置；忽略版本前缀和包修订号后仍不一致时明确提示，不把包更新冒充运行核心升级。
不适用字段不呈现；未检查、检查失败、未安装、版本未记录和版本不一致分别表达。
面板版本显示设备 owner 从安装记录或实际资源识别出的版本；文件存在但无法识别版本时，
主状态仍为“已安装，可使用”，不把候选版本当成当前版本。

页面打开仅读取设备缓存。页首统一“检查更新”按顺序查询面板发行源和软件包源，分别保留
检查时间与失败原因；不自动安装，也不因一个来源失败掩盖另一个结果。安装或更新仍逐项
确认，只有存在可执行候选才显示操作，不常驻无意义的灰色更新按钮。刷新设备状态使用
单一图标入口；Feed、架构和包明细归技术详情，依赖正常时折叠，缺失时展开。
Zashboard 保持标题工具区的独立入口，组件行也可打开完整面板；Nikki 后端明确由 Nikki
管理资源，不把静态资源伪装成软件包。

订阅与软件更新展示设备真实阶段、当前对象、已处理/总数及耗时，不用估算百分比。
操作进行中允许关闭弹窗，机场或组件页保留进度；短暂连接中断标为等待设备回读，执行失败、
正在恢复和恢复完成分别显示。只有操作进行中才轮询进度，普通页面不增加持续状态读取。
成功的软件包操作收为带对象和时间的最近更新或最近检查摘要；失败、执行中和恢复未确认
仍保留完整进度，不让旧的成功进度持续占据主区域。
Zashboard 资源检查与更新使用有界同步请求，显示进行中、结果或失败原因，不伪造下载
百分比或尚不存在的逐阶段操作记录。

所有页面保持“页面标题 -> 当前页面内容 -> 数据来源与新鲜度 -> 页面级操作”的顺序。数据来源只解释当前 UI 的读取状态，统一放在内容之后并紧邻刷新操作，不抢占首屏的业务信息层级。

页面标题右侧持续显示设备 owner 返回的 `NetFleet v<version> · <source commit 短号>`；该标识用于确认设备是否已经更新。完整 source commit 作为原生样式表 URL 的缓存键，生产 LuCI view 的菜单路径和安装文件名同时绑定 NetFleet 包版本，确保普通刷新也不会继续复用旧入口脚本。版本或部署身份缺失时明确显示“版本未提供”，不得由浏览器根据文件时间或缓存内容猜测。

- 概览：运行状态、出口摘要、机场/地区/最近决策摘要，面向快速扫描；不复制出口页的全部诊断字段；
- 出口：每个 capability 先显示当前路径、延迟、健康和选择方式；卡片标题和说明保持紧凑，不接受 LuCI 主题额外标题 padding；绑定的业务分类按“默认走此出口”和“默认直连、可临时切换”分开展示，并以可换行的紧凑分组呈现，不暴露“接管的原始策略组”等实现术语；运行时故障退路放在卡片末尾，选优口径和退出恢复另列；
- 机场与地区：以表格比较为主，表头、选中项、延迟、样本和空状态保持一致；机场页顶部保留自动更新、周期、最近执行、正常订阅数和最近结果的全局摘要，并提供紧凑的“管理订阅”入口：原生后端打开管理弹窗，Nikki 后端外部跳转其 Profile 页面；主体以机场为唯一行对象，把订阅状态与运行质量汇总到同一行，不再并列“订阅缓存”和“机场”两张重复表；机场“可用资源”的第一行是地区覆盖，第二行是 Mihomo 已加载节点的“可用/总数”，当原始订阅条目更多时同处补充“订阅 N 条”，候选地区组不能显示成节点；
- 配置：使用左侧分类、右侧内容和底部操作反馈，分类依次为“基础接入 / 网络接入 / 机场 / 地区映射 / 出口策略 / 业务规则 / 自动运行 / 安全与恢复 / 配置文件与备份”。策略编辑只从当前后端返回的订阅、已识别地区和策略基础的组中选择，新增/删除对象均使用明确的行级动作，不提供任意 policy JSON 或正则输入。网络接入与配置文件/备份使用独立读取、校验和确认操作，不受策略草稿的底部保存按钮控制；
- 事件与诊断：NetFleet 已确认完成的选路事件是主内容并排在最前；诊断状态随后只用指标组展示设备控制、事件存储、决策事件和当前连接，原始日志的保留口径使用独立辅助说明，不与实时状态伪装成同类指标。核心维护区提供确认后的重启、重载，以及按需读取的有界脱敏启动日志，核心控制接口不可用时仍能排查。当前活动连接只保留为默认折叠的辅助快照，详细规则命中链、流量和实时代理组观察交给 Zashboard。事件表和日志保持高密度，分页与刷新不遮挡内容，日志使用等宽字体和独立滚动区；不能把瞬时连接快照累计成持久规则频数。

## 高级实时观察面

内部导航只包含“概览 / 出口 / 机场 / 地区 / 配置 / 组件与更新 / 事件与诊断”七页。Zashboard 是外部完整工具，在页面标题右侧单列“Zashboard ↗”，不插入内部标签页。点击后使用上游接入页校验设备当前连接参数并进入完整页面，不嵌入 iframe、不增加 NetFleet 中转页，也不复制概览、机场或地区摘要。“事件与诊断”中的有限连接投影不冒充完整 Mihomo dashboard。

入口可用性来自同一次 status 的 Mihomo 运行、controller 可读和 `dashboard_lan_ready`；任一条件不满足时使用原生 disabled 状态，并在标题中给出最深可解释原因。Zashboard 保留上游完整功能，页面内临时选择、连接管理和其他 controller 操作按 Mihomo 当前运行态处理；NetFleet 自有页面继续独占持久 policy、订阅编排、服务启停和故障恢复。React 本机参考面只预览入口的位置、状态和反馈，不持有设备 controller 地址或密钥，也不伪造可用的 Zashboard 页面。

Nikki 后端使用 Nikki 已安装的资源和 controller；原生后端由 NetFleet 管理资源和 controller。URL 由同一个 NetFleet 入口按当前后端返回的连接信息构造，两种后端保持相同入口和独立完整页面，不建立第二 controller。

## 组件规则

- 导航：选中项使用主题强调色、浅背景和 3px 指示线；hover 只改变浅背景；
- 指标组：同一外框内使用分隔线，不为每个指标增加独立卡片；五项且内容简短的同类运行口径在宽屏保持单行，中等宽度按三项和两项等宽铺满，不能形成四项加一个孤立单元；不同语义的辅助说明不硬塞进指标组；
- 表格：浅色表头、稳定行高、细分隔线和轻量 hover；选中行使用主题浅背景；
- 机场详情：默认表只保留机场定位、可用资源、延迟、订阅状态、配额和到期时间；稳定订阅标识、缓存版本、最近尝试、订阅更新时间和最后测量属于按行展开的诊断信息，首次尚未运行 SubscriptionOwner 时显示“尚未执行”。订阅 owner 与运行状态 owner 在后端保持分离，由 status 的明确引用聚合，浏览器不得按机场显示名猜测关系；来源编辑通过独立管理弹窗，不在状态表中暴露地址和凭据；
- 结构编辑：新增机场只能选择当前后端尚未接管的订阅；新增地区只能选择该机场 cache 已识别的地区；新增出口能力需要稳定 ID、显示名和恰好一个入口组；业务组绑定只能选择当前策略基础已有组。业务规则选择域名后缀或 IPv4/IPv6 CIDR，目标为已有出口或直连；域名不含协议、路径或端口，CIDR 必须为合法网段。删除动作必须在本地草稿中同步清理引用，并在“查看变更”中逐项展示，真正写入仍由 `config_apply` 二次确认；
- 状态块：左边界颜色可以表达成功、警告或失败，正文仍保持正常文本色；
- 表单：标签和解释在左，控件在右；窄屏才改为上下排列；只读值与可编辑输入必须可区分；
- 订阅管理：原生后端在认证后的编辑弹窗显示设备当前订阅地址、用量地址和 User-Agent；User-Agent 使用 LuCI 可自定义下拉框，提供 `clash / clash.meta / mihomo` 预设并保留自定义值。弹窗有独立样式作用域和可收缩控件列，不复用配置页的宽列最小尺寸；地址只在页面内存中使用，不写入浏览器持久展示缓存。Nikki 后端仍跳转其订阅管理页；
- 网络接入：原生后端显示 DNS 上游与域名覆盖、LAN/本机代理范围、设备规则、监听端口和认证。TProxy 为当前适配模式，不提供未经接管与恢复验证的模式切换；不把 WAN/LAN 地址、任意路由或 nft 编辑放入该表单。已保存的密码只显示配置状态，修改凭据使用明确输入；
- 配置文件与备份：列表区分文件引用和可编辑状态，提供导入、下载、受控 JSON/YAML 编辑与删除；使用中的配置不允许直接覆盖或删除。备份导出与恢复是独立确认操作，明确提示包含私有凭据，不把正文放入普通状态缓存；本机 React 只预览文件元信息和交互，不获取配置或备份正文；
- 操作：主操作使用主题色，普通操作保持中性，破坏性操作使用危险色；同区块内的次级外部跳转使用紧凑文字链接和外部标记，不与页面级操作竞争；禁用态必须同时有视觉和原生 `disabled`；
- 焦点：键盘焦点使用主题色轮廓，不依赖颜色变化之外的隐式反馈；
- 空状态与错误：解释当前事实和下一步，不伪造零值，不使用大面积插画。

未配置设备不显示伪造的概览零值，也不因 `status` 缺少 policy 而整页报错。页面先调用只读
onboarding preview，显示识别到的原生恢复配置、机场数量、真实可用地区和将接管的入口组。
预检通过时主操作为“按推荐配置开始接管”，旁边提供“检查详细配置”；主操作必须二次确认，
明确说明会由所选后端应用运行配置并接管网络。预检不通过时逐项显示可行动阻断原因且不出现可用的接管按钮。
浏览器不解析节点或生成 policy，所有发现、revision 和事务结果来自设备 RPC。

## 性能与实现约束

视觉统一不得增加设备 RPC、自动轮询、后台进程或运行状态。空闲请求数、status/events 读取次数和 mutation owner 均由[公开接口与 UI](../architecture/interfaces.md)约束。

网络配置、文件列表和核心日志按进入对应分区或显式刷新读取，不并入每次 status。
本机 React 桥接仅消费脱敏状态并保留内存草稿，设备写入由认证后的 LuCI 完成；具体管理
与恢复边界见[设备独立管理](../architecture/management.md)。

CSS 使用 scoped token 和现有 DOM，不引入 JavaScript 主题计算。配置草稿可以继续在用户编辑时重绘当前原生 DOM；当前数据规模不需要虚拟列表。只有实际出现数百到上千可见行并取得浏览器性能证据后，才考虑局部更新或虚拟化。

## 可访问与窄屏底线

交互元素保留语义化 button、label、table 和原生 disabled 状态。文本与背景需保持可读对比度；状态不能只靠颜色表达。电脑端是主要验收面，`700-760px` 以下只要求导航可达、操作不重叠、内容不裁切、表格可横向滚动，不为移动端重排或删减业务信息。
