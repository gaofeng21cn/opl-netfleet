# NetFleet UI 设计合同

本文是 NetFleet 当前视觉语言、页面组织和交互呈现的唯一详细设计合同。
[当前架构](../architecture/overview.md)继续负责产品对象、状态 owner、RPC、动作和安全边界；本文不重复或改写这些运行合同。

## 产品气质

NetFleet 是面向电脑使用的 OpenWrt 网络运维界面。页面应安静、清晰、紧凑，优先支持扫描、比较和重复操作，不采用营销页、移动应用或装饰性仪表盘的表达方式。

界面遵循以下原则：

- 信息层级先于装饰：页面标题、来源状态、主要内容、辅助诊断和操作反馈从上到下稳定排列；
- 状态颜色只表达需要辨认的状态：绿色只用于健康指示和明确成功反馈，普通运行值、当前选择与合格延迟使用主题强调色；
- 主题色负责选择和动作：导航选中、主按钮、输入焦点和步骤进度跟随当前 LuCI 主题；
- 同类信息使用同一容器：指标、表格、配置行、恢复说明和日志分别使用稳定的组件形态；
- 桌面优先：主要布局针对常见电脑宽度设计，窄屏只保证内容可达、文字不重叠、表格可横向滚动。

## 双宿主边界

本机 React/Vite 页面用于快速评估信息、交互和视觉节奏；设备端原生 LuCI 页面是唯一生产部署实现。两者共享页面名称、可见文案、状态语义、密度和视觉 token，不共享组件代码，也不要求逐像素一致。

生产 LuCI 不加载 React、组件库、远程字体或额外运行时。视觉统一只能通过原生 `view.extend`、`E()` 和 scoped CSS 完成。

## 颜色与主题

设备端颜色从 LuCI 主题变量投影到 NetFleet token。优先级如下：

| 用途 | NetFleet token | LuCI 来源或默认值 |
| --- | --- | --- |
| 选择、焦点、主操作 | `--nf-accent` | `--primary` -> `--primary-color-high` -> `#5e72e4` |
| 浅强调背景 | `--nf-accent-soft` | `--primary-color-low` -> `rgba(94, 114, 228, 0.10)` |
| 正文 | `--nf-text` | `--text-color-high` -> `#202124` |
| 辅助文字 | `--nf-muted` | `--text-color-medium` -> `#5f6368` |
| 页面与容器背景 | `--nf-page` / `--nf-surface` | LuCI background token -> 中性灰 / 白 |
| 边界 | `--nf-border` | `--border-color-medium` -> 中性灰 |

`OPL` 标识可以保留品牌红；健康指示和明确校验成功使用绿色，注意使用橙色，失败和破坏性动作使用红色。正常运行、已启用、可读取、当前使用和合格延迟是主题层级，不用绿色铺满页面。任何地区、机场、出口或导航项不得因为业务身份获得专属装饰色。

## 尺度与排版

- 页面最大内容宽度为 `1440px`；常规内容使用 `15px` 基准字号和约 `1.5` 行高；
- 页面标题为 `24-28px`，分区标题为 `17-21px`，表格正文不低于 `13px`；
- 控件高度使用 `38-46px`，确保桌面鼠标操作稳定且文字不拥挤；
- 间距以 `4 / 8 / 12 / 16 / 20 / 24px` 为基础序列；
- 容器圆角统一为 `6px`，不用大圆角胶囊或层层嵌套卡片；
- 字距固定为 `0`，不随视口缩放字号。

## 页面骨架

所有页面保持“页面标题 -> 当前页面内容 -> 数据来源与新鲜度 -> 页面级操作”的顺序。数据来源只解释当前 UI 的读取状态，统一放在内容之后并紧邻刷新操作，不抢占首屏的业务信息层级。

页面标题右侧持续显示设备 owner 返回的 `NetFleet v<version> · <source commit 短号>`；该标识用于确认设备是否已经更新。完整 source commit 作为原生样式表 URL 的缓存键，生产 LuCI view 的菜单路径和安装文件名同时绑定 NetFleet 包版本，确保普通刷新也不会继续复用旧入口脚本。版本或部署身份缺失时明确显示“版本未提供”，不得由浏览器根据文件时间或缓存内容猜测。

- 概览：运行状态、出口摘要、机场/地区/最近决策摘要，面向快速扫描；不复制出口页的全部诊断字段；
- 出口：每个 capability 先显示当前路径、延迟、健康和选择方式；卡片标题和说明保持紧凑，不接受 LuCI 主题额外标题 padding；绑定的业务分类按“默认走此出口”和“默认直连、可临时切换”分开展示，并以可换行的紧凑分组呈现，不暴露“接管的原始策略组”等实现术语；运行时故障退路放在卡片末尾，选优口径和退出恢复另列；
- 机场与地区：以表格比较为主，表头、选中项、延迟、样本和空状态保持一致；
- 配置：使用左侧分类、右侧内容和底部操作反馈，首次设置向导沿用相同字段组件；
- 事件与诊断：NetFleet 已确认完成的选路事件是主内容并排在最前；诊断状态随后只用指标组展示设备控制、事件存储、决策事件和当前连接，原始日志的保留口径使用独立辅助说明，不与实时状态伪装成同类指标。当前活动连接只保留为默认折叠的辅助快照，详细规则命中链、流量和实时代理组观察交给 Zashboard。事件表和日志保持高密度，分页与刷新不遮挡内容，日志使用等宽字体和独立滚动区；不能把瞬时连接快照累计成持久规则频数。

## 高级实时观察面

当前生产 UI 没有内置 Zashboard，“事件与诊断”中的有限连接投影也不冒充完整 Mihomo dashboard。长期定位由[设计白皮书](../product/whitepaper.md)负责，待实现边界见 [Zashboard 集成方案](../proposals/zashboard-integration.md)；实现完成后，桌面导航在“地区”和“配置”之间增加“实时运行”，只对声明兼容观察能力的当前后端显示。

“实时运行”使用完整内容宽度承载固定版本的 Zashboard 静态页面，不再包一层装饰卡片，也不复制 NetFleet 概览、机场或地区摘要。页面沿用 NetFleet 顶部的数据来源、连接状态和新鲜度表达；Zashboard 本体按 LuCI 明暗主题选择最接近的原生主题，并在用户打开页面时才加载，离开后不得继续制造 NetFleet RPC 或后台轮询。

该页面以观察连接、流量、内存、规则命中、代理组和 Provider 状态为主。配置、核心、版本、连接关闭和内部 selector 控件必须隐藏、禁用或被同源桥接拒绝；需要保留临时改路时，只显示 manifest 明确公开的用户 selector，并通过 NetFleet 的白名单命令和 owner readback 完成。controller 地址和 secret 不作为表单显示，不进入 URL、DOM、浏览器缓存或 localStorage。当前 source 没有满足这些条件的桥接和集成页面，因此设计稿和本机 React 预览也不能把它标记为已经可用。

## 组件规则

- 导航：选中项使用主题强调色、浅背景和 3px 指示线；hover 只改变浅背景；
- 指标组：同一外框内使用分隔线，不为每个指标增加独立卡片；五项且内容简短的同类运行口径在宽屏保持单行，中等宽度按三项和两项等宽铺满，不能形成四项加一个孤立单元；不同语义的辅助说明不硬塞进指标组；
- 表格：浅色表头、稳定行高、细分隔线和轻量 hover；选中行使用主题浅背景；
- 状态块：左边界颜色可以表达成功、警告或失败，正文仍保持正常文本色；
- 表单：标签和解释在左，控件在右；窄屏才改为上下排列；只读值与可编辑输入必须可区分；
- 操作：主操作使用主题色，普通操作保持中性，破坏性操作使用危险色；禁用态必须同时有视觉和原生 `disabled`；
- 焦点：键盘焦点使用主题色轮廓，不依赖颜色变化之外的隐式反馈；
- 空状态与错误：解释当前事实和下一步，不伪造零值，不使用大面积插画。

未配置设备不显示伪造的概览零值，也不因 `status` 缺少 policy 而整页报错。页面先调用只读
onboarding preview，显示识别到的原生恢复配置、机场数量、真实可用地区和将接管的入口组。
预检通过时主操作为“按推荐配置开始接管”，旁边提供“检查详细配置”；主操作必须二次确认，
明确说明会切换 Nikki Profile。预检不通过时逐项显示可行动阻断原因且不出现可用的接管按钮。
浏览器不解析节点或生成 policy，所有发现、revision 和事务结果来自设备 RPC。

## 性能与实现约束

视觉统一不得增加设备 RPC、自动轮询、后台进程或运行状态。空闲请求数、status/events 读取次数和 mutation owner 均由[公开接口与 UI](../architecture/interfaces.md)约束。

CSS 使用 scoped token 和现有 DOM，不引入 JavaScript 主题计算。配置草稿可以继续在用户编辑时重绘当前原生 DOM；当前数据规模不需要虚拟列表。只有实际出现数百到上千可见行并取得浏览器性能证据后，才考虑局部更新或虚拟化。

## 可访问与窄屏底线

交互元素保留语义化 button、label、table 和原生 disabled 状态。文本与背景需保持可读对比度；状态不能只靠颜色表达。电脑端是主要验收面，`700-760px` 以下只要求导航可达、操作不重叠、内容不裁切、表格可横向滚动，不为移动端重排或删减业务信息。
