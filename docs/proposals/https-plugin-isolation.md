# HTTPS 插件故障隔离

本文面向 NetFleet 平台与插件开发者，回答可选 HTTPS 协议转换如何独立演进且不扩大
基础网络故障范围。它描述待实现的隔离边界；当前能力分别以
[微内核](../architecture/microkernel.md)和[HTTPS 兼容](../architecture/https-compatibility.md)为准。

## 目标与边界

应用保持原始 URL。管理员明确选择设备和域名，HTTP/1.1 请求按策略转为上游 HTTP/2；
已使用 HTTP/2 或未命中的连接沿原路径。模块关闭、未安装或失败均保留原有 NetFleet
选路。故障瞬间的在途连接可能中断，模块不重放 POST，也不承诺原路径业务总能成功。

默认产品的基础插件存在明确依赖关系，并非全部都能随意卸载；HTTPS 属于可选增强。
可选增强依赖基础能力，基础启动、停止、订阅与配置管理不得反向依赖增强健康。

| 对象 | 唯一责任 |
| --- | --- |
| 基础网关 | DNS、默认选路、TPROXY、核心生命周期、接管许可及其内核到期、基础清理 |
| HTTPS 插件 | 设备与目标配置、私有 CA、TLS/HTTP 转换、插件健康和自己的连接排空 |
| 插件宿主 | 能力准入、独立进程与资源限制、调用超时、插件安装更新和故障状态 |
| UI | 模块开关、实际状态、目标规则、接入与诊断；只投影后台事实 |

## 实现方向

当前低权限进程、CA 投影与强制资源上限见[HTTPS 兼容](../architecture/https-compatibility.md)。
后续文件系统沙箱应把可见数据进一步收敛到本插件配置、证书和运行目录，保持稳定 CA 字节。

接管通过现有 gateway owner 提供的有限租约操作完成，参数仅包含已验证的来源、目标、
端口、监听身份和期限；不能提交 nft 脚本、命令、任意路由表或文件路径。owner 校验端口、
mark、设备及出口等价性，限制许可范围与数量。插件更新无需修改宿主网关实现。
首期复用现有精确目标与十秒租约语义，不扩展为全流量解密。

后台探测释放全局锁的现有合同见[HTTPS 兼容](../architecture/https-compatibility.md)。
后续把插件健康循环从基础生命周期观察进一步移出，形成独立调度。
基础关闭立即禁止新租约，再独立清理基础接管。插件异常或清理失败不能跳过基础清理。

现有 cgroup 与文件描述符预算需用实际上传和 SSE 并发负载调优；单文件大小限制仍需
补充为日志与临时磁盘总量约束。通用插件准入也应复用已经验证的进程隔离能力。

更新事务只替换本插件及明确缺失的依赖，不升级基础产品或代理核心，不卸载共享依赖。
依赖接口不兼容时拒绝该插件候选并保持旁路。安装前完成依赖闭包、空间和回退检查；
独立插件更新应接入[软件包事务](../architecture/packaging.md)的持久恢复机制，
保持设备包数据库、文件和服务的恢复事实，不另建恢复 owner。

## 管理与验收

HTTPS 的全部业务控制位于组件详情页。总开关表示用户意图，状态单独显示接管、旁路、
故障和排空连接数；基础 NetFleet 保有自己的启动入口。关闭、停用插件及撤销信任都先
撤销新连接接管，后台恢复不得推翻用户关闭。

将隔离验证收敛为可复用插件准入测试：安装、升级、停用、卸载、崩溃、卡死、资源超限、
管理链失效、过期 revision 和中断恢复。对每种故障，验证非目标连接、基础核心 PID、
基础配置及选路不受影响，新的目标连接在许可到期后回到原路径；基础关闭不得依赖插件
响应。HTTPS 另外验证证书、H1/H2、上传、SSE、取消和未命中域名的原路径。

基础平台修复和插件发布分别取得资格与 canary 证据。平台隔离能力形成稳定接口后，
普通插件版本只运行插件准入与自身协议检查；只有实际修改基础 owner 时才增加基础网络
回归。源码、隔离 VM、安装与真实业务证据仍分别报告。
