# HTTPS 控制开销与独立插件开发

本文面向 HTTPS 插件维护者，回答如何降低管理开销并缩短插件开发循环。它是待实施方案，
不改变 [HTTPS 当前合同](../architecture/https-compatibility.md)、
[插件隔离边界](../architecture/microkernel.md)或现有设备准入规则。

## 目标与边界

优化的第一写集是 HTTPS 引擎包中的 ucode 管理层及其私有工具。HAProxy、基础网络配置、
Mihomo 进程、DNS、TPROXY、客户端 URL 与一次性信任保持原合同。Device identity 是独立
插件，只通过当前证据接口消费其结果。若测量证明成本在 gateway owner 内，应另列
Mihomo 插件修改，不把共享接口变化伪装为单插件内部替换。

不承诺插件崩溃时在途请求不中断。验收要求是不扩大到未命中业务、不停止基础网络、
新连接在现有十秒租约到期后恢复原路径。资源隔离和包独立均不能单独证明这些行为。

## 测量后再优化

在同一 VM、固定基础包与配置上比较旧、新插件；保留 DNS 缓存和连接冷暖状态说明。
分别测关闭、开启无业务、固定并发 SSE/上传、相同负载加 UI 轮询四种场景。预热后每场景
至少五分钟，重复三次，按 cgroup 统计管理层及子进程、HAProxy 和基础 Mihomo 的 CPU、
内存、节流；另测管理轮次耗时分位数、锁持有时间、子进程数、续租间隔和请求失败率。
探针与真实业务请求分别计数，不能把管理 cgroup 的 CPU 全归因于管理脚本自身。

先增加仅开发测量使用的阶段耗时记录，拆分状态读取、两栈处理链探针、地址同步、gateway
调用、规则同步和状态落盘。默认生产关闭记录，不保存业务数据。此前短采样只能作为
优化动机，不能替代该基线或说明所有断流的根因。

## 实施顺序

1. 保留每两秒健康轮次与十秒租约。在 HTTPS 私有层消除同轮重复读取、无变化的 JSON
   规范化和规则映射计算；缓存按配置、CA、引擎 PID/启动时间及 revision 失效。
   地址 TTL 每轮仍检查，不用缓存延长有效期；用户动作与错误立即失效缓存。
2. 降低探针启动和 TLS 固定成本。当前每轮新建 IPv4、IPv6 的完整 H1→H2 回环连接，
   可先用一次有界原生工具调用完成两栈验证，保持每栈新连接、证书验证、NAT 和实际
   H2 往返；不得用复用连接掩盖新建连接链路损坏。单次工具仍受原截止时间与资源限制。
3. 将纯展示摘要和不变配置计算移出每轮管理工作；必要心跳仍持久发布。页面读取使用
   有界的新鲜度说明，不能用旧快照授权开启、续租或写配置。
4. 如以上收益不足，单独测量 gateway 的续租准入：现有续租会读配置、检查监听者、
   校验选路、获取基础快照并执行 nft 事务。优化应由 gateway owner 在明确 epoch 与
   失效规则下完成，保留真实内核与进程检查；HTTPS 不增加第二个 nft owner。

不把提高 CPU 限额、延长十秒租约或减少必要的故障检查当作性能优化。不先引入新常驻
daemon、第二套 supervisor 或重写 HAProxy。任何减少检查频率的提议都先作为独立合同
变化论证，不能混入内部去重补丁。

## 开发与更新闭环

当前入口见[插件开发](../development/plugins.md#官方插件轻量验收)。通用 SDK、可选 APK
构建、真实 OpenWrt 无 Python 诊断和包生命周期已经存在；它们不是零依赖沙箱，也还
不能用一份插件诊断回执代替正式资格。

进一步收敛环境时，在固定且已合格的基础包上只替换待测插件，测试客户、TLS origin、
CA 和 DNS 全部使用隔离夹具；依赖插件作为固定测试基座，不复制其实现。构建只产出
发生改变的包，记录插件包与基座身份、接口 major、版本约束及测试集合。首次建设基座
或修改宿主/gateway 合同时跑完整资格；仅内部变化仍需插件功能、安装/更新/失败回退/
卸载和基础不受影响的集成测试。新的增量资格只有在发布与安装 owner 能校验其身份、
范围和基座适配之后才可用于发布；不能直接将 diagnostic 的 qualified 改成 true。

更新流程先保存配置、CA、加载状态和旧签名包，撤销新接管并排空，失败保留旧包。
只替换本次变化的包，恢复原开关与加载状态，验证协议和基础路径。不因依赖已安装就
重新安装它们，不更新内核或整套产品；依赖不满足时先报告精确的最小依赖变更。

## 验收目标

性能目标先定为同机同场景管理 CPU 相对基线下降至少 50%，开启无业务时争取低于
单核 5%；这是待测目标，不是现有能力。真实业务 p95 时延不劣化超过 5%，吞吐不下降，
内存不增加，健康轮次 p99 小于一秒；低延时场景同时报告绝对毫秒和波动区间。

故障测试必须保持现有两秒检查、十秒到期、三十秒恢复、第三次独立故障锁定、用户关闭
优先与不重放 POST。覆盖管理/引擎崩溃和卡死、地址冲突/过期、单规则失败、共享 IP、
证书失败、更新中断、卸载和排空失败。核对基础 PID、配置、DNS、TPROXY 与未命中业务；
CPU/内存/进程资源压力也在 VM 中验证，不能仅测进程退出。

通过后再做有界实机 canary，保留旧插件回退。长时间业务观察与 QEMU 是不同证据层，
任何单次成功不能证明永不故障。
