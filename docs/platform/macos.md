# macOS 平台实现

本文是 macOS 机制事实的当前 owner：界面宿主与资源加载、运行与进程监督、私有状态与凭据位置、
配置与订阅存储事务、流量接管原语和打包签名。共享产品对象、选择算法、恢复顺序和界面
内容与交互分别由[产品对象](../architecture/domain-model.md)、[选择](../architecture/selection.md)、
[运行与恢复](../architecture/runtime-and-recovery.md)和[界面设计](../design/ui.md)拥有；本机构建、
启动与验证的操作入口见[macOS 开发](../development/macos.md)。

macOS 不复制选择算法，不包含透明 HTTPS 兼容插件或 LAN 网关管理。

## 界面宿主与资源加载

业务界面由 `ui/` 的 React 桌面入口提供，通过带会话认证的客户端连接本机服务；页面内容、
布局、状态语义、操作层级和宿主职责边界见[界面设计](../design/ui.md)。macOS 以 AppKit 窗口、
应用菜单、菜单栏状态项、快捷键、文件面板和生命周期实现这些职责，原生菜单只向页面发送
操作意图，UI 不直接操作核心、系统代理或 TUN。

构建时将 Vite 的静态产物装入应用 `Resources/desktop/web`，运行时不启动 Vite、不加载设备
预览桥或模拟场景；本机 Web 服务只提供固定入口和构建产物中的静态资源，不开放源码或本机目录。
桌面布局覆盖集中在 `ui/src/desktop/desktop.css`，不修改 OpenWrt 的布局；应用图标在构建时由
仓库 logo 生成 macOS 图标尺寸；图案居中占画布 82%，保留透明安全边距，避免 Dock 中的视觉尺寸大于系统图标。侧栏继续使用原 logo。

## 运行与进程监督

桌面运行由本机 Node 进程协调，UCode 微内核加载同一份模型、编译、选择与恢复业务服务。
macOS 提供平台路径、凭据、Profile、订阅、进程与 Mihomo 后端服务，明确替换 OpenWrt 实现；
不能把 UCI、procd、nft 或 APK 的状态解释为 macOS 状态。窗口关闭不等于停止代理；退出应用
必须完成自身网络状态恢复。

### 组合根与替换面

共享业务实现在 `openwrt/files/usr/libexec/opl-netfleet`，该目录下的内核、模型、编译、选择、
证据与恢复插件由两个平台共同消费；macOS 构建时把它复制为应用的 `Resources/shared`，再叠加
`desktop/ucode`，因此同名路径以桌面副本为准。平台差异集中在两个组合根：
`openwrt/files/usr/share/opl-netfleet/system.json` 与 `desktop/ucode/system.json`。

`desktop/ucode` 提供 `platform-macos` 插件、桌面入口 `main.uc`、宿主适配器与文件桥。macOS
组合根用显式重绑替换平台服务（路径、运行时、进程、Profile、凭据、订阅、文件与 Mihomo
后端），并只绑定本平台使用的共享服务：没有 gateway、TProxy 拦截与设备部署面。桌面宿主
调用的 owner 命令、以及每个已绑定服务的依赖闭包，由 `tests/test_platform_composition.py`
按内核解析语义静态校验，不需要 UCode、设备或已构建应用即可发现另一平台的漂移。

显式代理核心由持有桌面所有权管道的独立父进程监督，管道断开后停止并回收核心；启动时核对
持久 PID、启动时间与命令身份，清理上次自身遗留进程，不按进程名称批量终止代理。

## 私有状态与凭据

每个状态目录先取得内核文件锁，再读取或修改状态、socket 和业务代码投影；探活本身不授予
替换运行入口的权限。用户私有目录保存 policy、evidence、recovery、订阅缓存、原生配置、运行
状态及操作锁；订阅更新记录由共享 SubscriptionOwner 写入状态目录的 `subscription-history.json`，重启后继续读取同一份记录。目录与文件分别使用 0700、0600；订阅凭据和控制密钥不得进入状态摘要、日志或
仓库。

导入和备份恢复拒绝任意路径写入，候选配置先经真实 Mihomo 校验再原子保存；正在使用的配置
不能被导入直接覆盖，失败保持之前可运行状态或恢复直连。

## 配置编辑与策略所有权

结构化配置编辑复用共享配置编辑器的资源与版本投影，提交草稿起始 revision；策略合并与未知
字段保留由共享 owner 完成，macOS 不重建 policy。增强代理运行中不接受仅保存结构化配置，
需先停止或退出增强，再保存、编译并按需启用。

构建器从共享 `policy-sources/base-v1.json` 与 `rulesets.lock.json` 准备 `Resources/builtin`，
按同一锁文件的 URL、大小和 SHA-256 获取规则，不在应用启动时联网下载。桌面 owner 取得
状态锁并停止自身旧核心后，先验证完整规则集，再将策略投影到私有 `policy-sources`、MRS
投影到 `backend/run/rulesets`。订阅写入不接触这些资源。

Zashboard 面板用同一方式固定：`scripts/macos/dashboard.json` 记录上游 release、资产名、
大小和 SHA-256，构建器校验 ZIP 结构后把 `dist/` 装入 `Resources/dashboard`，并随包提供
上游许可证。桌面运行时会把它复制到核心工作目录内的私有 `ui` 目录，再把
`external-ui` 指向该副本——Mihomo 只服务自身工作目录（或显式 `SAFE_PATHS`）内的路径，
因此面板不直接从应用包读取。TUN 会话由特权组件把同一份副本再次复制到 root 私有状态后
交给 root 核心，源路径必须位于当前用户的私有状态目录内。设备端仍由自身 dashboard 插件
管理它自己的副本；“核心与网络”的更新面见下文。

### 面板更新

面板的当前所有者副本位于私有状态目录，随包资源只负责首次播种。用户在“核心与网络 →
更新”里显式检查时，本机 owner 以有界 HTTPS 请求读取上游 release 元数据，要求 tag、
资产名、下载地址、大小与 `sha256:` 摘要全部成立，并把候选缓存到 `updates.json`（24 小时
内复用，不重复联网）。安装是独立的确认动作：先按声明大小与 SHA-256 校验下载内容，再用
受限 ZIP 读取器展开，只接受纯 `dist/` 普通文件，拒绝链接、目录穿越、加密条目和超出
文件数/总字节上限的内容；随后按文件原子替换私有副本并清理新清单不再包含的旧文件。
运行中的核心按请求读取该目录，因此不需要重启，也不会看到缺失路径。任何一步校验失败都
保持旧副本与旧版本记录。

### 应用自更新

应用更新的信任锚就是 Apple 代码签名与公证，没有第二套密钥：Developer ID 证书已经承担
签名职责，再加一份清单私钥只是把同一个信任问题重复一次，还要用户额外保管密钥。GitHub
Release 为每个资产提供 `sha256:` 摘要，用于下载内容的完整性校验；来源身份由签名与公证
证明——即使账号被冒用上传了别的包，也无法用本产品的 Developer ID 证书签名并通过 Apple
公证。

检查时从 `releases?per_page=20` 选出 tag 形如 `macos-vX.Y.Z` 且非草稿、非预发布的最高
版本，并要求 Release 同时提供 DMG 资产与 GitHub 计算的 sha256 摘要；没有摘要的 Release
只作为手动下载入口。安装是独立确认后的动作：下载后先比对大小与摘要，再挂载只读镜像并
验证其中的应用——`codesign --verify --deep --strict`、Developer ID 授权、Team ID 与产品
一致（`SVVC4TA784`）、`build.json` 为干净的分发构建且版本与 Release 相符，最后要求
Gatekeeper 评估通过并已装订公证票据；任一步失败都不进入暂存，镜像始终会被卸载。

替换在应用退出后进行，由独立进程完成：等待当前应用 PID 消失，把现有应用移到单槽备份，
复制新应用、重新校验签名后清隔离属性并重启；交换前失败保持目标不变，交换后失败恢复备份
并重开旧版本，同时写入回执。退出本身复用既有优雅退出路径，因此更新前一定先停止核心并
撤销系统代理或 TUN，清理未确认就不会继续。

自更新只对 `channel=distribution` 的 Developer ID 构建开放；本地、开发与含未提交改动的
构建会拒绝并在界面说明原因。源码运行没有安装身份时只报告上游版本，不宣称可更新。

特权网络组件（helper 与 root 核心）是独立于应用包的副本：应用更新后它们可能落后于包内
版本，"核心与网络"会按字节比较报告状态，需要时由用户重新授权安装，应用不在后台静默提升
权限。

### 面板更新

面板的当前所有者副本位于私有状态目录，随包资源只负责首次播种。用户在“核心与网络 →

内复用，不重复联网）。安装是独立的确认动作：先按声明大小与 SHA-256 校验下载内容，再用
受限 ZIP 读取器展开，只接受纯 `dist/` 普通文件，拒绝链接、目录穿越、加密条目和超出
文件数/总字节上限的内容；随后按文件原子替换私有副本并清理新清单不再包含的旧文件。
运行中的核心按请求读取该目录，因此不需要重启，也不会看到缺失路径。任何一步校验失败都
保持旧副本与旧版本记录。

### 应用自更新

应用更新沿用同一套"先验证、后替换"的形状，但信任锚是 Apple 代码签名而不是面板摘要：
发布流程用 Ed25519 私钥对清单签名，应用内置对应公钥，只有清单签名成立、镜像大小与
SHA-256 一致，且新包通过 `codesign --verify --deep --strict`、`spctl --assess`、
`stapler validate`、Team ID 与当前应用一致、包内 `build.json` 为干净的分发构建并与清单
版本/提交一致时，才认为候选可安装。安装前重新下载并验证签名清单，不复用检查阶段的缓存
结论。

替换在应用退出后进行，由独立进程完成：它等待当前应用 PID 消失，把现有应用移到单槽备份，
复制新应用、重新校验签名后清隔离属性并重启；任何一步失败都会把备份放回原位并重新打开旧
版本，同时写入回执。应用未退出时绝不替换正在运行的包。退出本身复用既有的优雅退出路径，
因此更新前一定先停止核心并撤销系统代理或 TUN，清理未确认就不会继续。

自更新只对 `channel=distribution` 的 Developer ID 构建开放；本地、开发、含未提交改动的
构建以及未内置公钥的构建都会拒绝并在界面说明原因。源码运行没有安装身份时只报告上游
版本，不宣称可更新。签名私钥默认位于 `~/.config/opl-netfleet/update-signing-key.pem`
（0600，必须自行备份，丢失后需要随新构建重新分发公钥）；公钥随包分发，路径为
`scripts/macos/update-key.pub`。

特权网络组件（helper 与 root 核心）是独立于应用包的副本：应用更新后它们可能落后于包内
版本，"核心与网络"会按字节比较报告状态，需要时由用户重新授权安装，应用不在后台静默提升
权限。

`use-builtin-policy` 在核心停止时调用共享模型生成候选；受同一串行入口管理的文件事务
在完成共享 Schema 与真实核心编译后提交，失败恢复旧 policy。升级不自动覆盖已有策略。

## 订阅来源事务

桌面添加订阅由本机 owner 下载并经真实核心校验，提交前不改现有来源。来源字段校验与配额解释调用 `models.subscriptions`，地区发现和策略合并调用
`configuration.onboarding-model`；Node 宿主不维护 provider/地区合并规则。首次添加调用共享内置策略草拟；
订阅完整配置只保存在独立恢复位置，只有节点列表时为恢复生成最小主入口。保存后自动编译；过程不启动核心、不修改网络接入。一个订阅只生成一个来源，不额外复制为本地导入机场；
合并和删除保护遵守[订阅接入合同](../architecture/management.md#订阅接入与策略归属)。

来源增删、启停和地址修改须先停止核心，正常订阅更新允许在运行中使用共享更新及回退链路；
失败下载保留旧缓存。当前桌面订阅表单不提供独立 info URL 或手工月重置日。已保存但无法自动识别或编译的订阅标记待配置，不报告可用。

## 网络接入

接入方式与业务运行模式相互独立：接入方式是显式代理、系统代理或 TUN，业务模式是原生直连、
Mihomo 原生代理或 NetFleet 增强代理。首次启动使用显式代理，只监听回环，不改变系统网络；
系统代理必须在核心就绪后接管；TUN 必须经过特权服务授权并读取真实核心与网络结果，只写入
`tun.enable` 不能报告接管成功。缺少权限或遇到冲突时保持原网络并返回具体原因。

系统代理与 TUN 需要安装本应用随包提供的有限特权组件并由 macOS 管理员授权，安装不等于接管
成功；显式代理不需要特权组件。每个核心与网络资源只有一个管理者，系统设置保存接管前状态，
清理只恢复仍属于当前操作的字段，第三方后续修改不得被旧快照覆盖。核心或桌面进程异常退出
必须触发网络清理，无法证明清理成功时呈现未确认，不冒充直连。用户在核心异常退出后重新启动时，桌面 owner 先确认停止与接管清理，再清除旧启用状态并重新编译、启用；清理失败不得继续。退出增强恢复独立 Recovery
Profile；显式直连停止核心与调度并撤销自身接管。

TUN 接入已有 DNS 缓存时可能只看到目标 IP。未自定义嗅探设置的配置默认从 HTTP Host、
TLS/QUIC 握手识别域名，使内置域名规则和双出口选择仍然成立；不解密 HTTPS 内容。
显式的 Profile 嗅探配置保留。此机制只属于 macOS TUN 投影，不改变共享业务规则。

### 核心设置与运行组件投影

本机快照同时给出只读的 `core` 投影，供界面显示“核心与网络”。它只组合三层已有的真实事实：
Profile 声明值、`CoreOwner.projectProfile` 交给核心的投影值、以及运行中核心的 controller
回读；界面不重新实现映射，也不把三层合并成第二个配置事实源。强制值与 Profile 声明值不同的
行标为平台接管，未声明的行标为核心默认。

TUN 会话专属参数由特权组件报告，而不是由界面推测：`prepareTun` 在写入会话配置时记录本次实际
应用的有界覆写（DNS 接管与监听移除、TUN 设备与协议栈、自动路由、DNS 劫持、默认嗅探和端口），
只在会话运行期间随 helper 状态返回。没有会话时不显示这些行，也不把 `projectProfile` 里
尚未被会话替换的值说成 TUN 实际值。覆写记录不包含 controller secret、订阅凭据或完整配置。

运行组件按随包二进制现场回读版本（Node 取当前进程身份、Mihomo 与 yq 执行自身版本命令）；
UCode 没有版本开关，退回随包清单里的固定源码身份。应用构建身份同样来自包内
`Contents/Resources/build.json`，由平台路径交给共享 `status.build` 投影，与设备页使用同一字段形状。

## 打包与签名

应用由本地构建入口生成 `.app`，内含固定版本的 Node、UCode、Mihomo 和 yq，包内动态库使用
相对路径。本地构建使用 ad-hoc 签名；分发构建使用 Developer ID Application、hardened runtime
和可信时间戳。只有 Node 启用 V8 所需的 `allow-jit` entitlement。源码运行、签名、公证和
下载后首次运行是独立证据层，
构建与验证入口见[macOS 开发](../development/macos.md)。

macOS 平台版本与构建修订由 `desktop/app/Info.plist` 的 `CFBundleShortVersionString`、
`CFBundleVersion` 唯一维护。构建器从同一源码读取这些值，连同完整 `source_commit`、
`source_tree`、架构、渠道与 dirty 标志写入签名覆盖的 `Contents/Resources/build.json`，
外部 `build-receipt.json` 使用相同字段并附带构建检查结果。原生“关于”窗口显示平台版本、
修订、渠道与短提交号；完整身份以包内文件为准。

默认构建标记为 `development`，未提交改动必须显示。`--require-clean-source` 在依赖准备
前拒绝 dirty 源码，成功产物标记为 `local`；提交或工作区清洁状态在构建期间变化时拒绝
替换原应用。`local` 只表示干净源码的本地交付构建，不表示已安装、已公证或公开发布。
同时指定 `--signing-identity` 时渠道为 `distribution`，该值只标记签名分发构建，不证明公证
或发布完成。DMG 打包入口要求应用已公证并 staple，DMG 自身仍需公证、staple 和最终
虚拟机验收；具体命令归[开发指南](../development/macos.md#签名与-dmg)。

## 本机接口

界面 HTTP 仅监听回环地址，使用每次启动生成的随机令牌，并限制来源和请求大小。私有 Unix
socket 供当前 UCode 调用平台方法，socket 和所在目录限定当前用户访问，浏览器不可使用该
接口。用户操作串行，调度器复用同一入口，平台回调不得建立第二轮选优。连接诊断只返回本应用
所管理核心的连接摘要；控制接口读取失败时报告失败，不伪装为空列表。

## 桌面布局与系统交互

macOS 客户端复用 `ui/` 的 React 桌面入口和同一套侧栏、概览、出口面板、机场/地区表格与事件组件，按实际能力提供概览、出口、机场、地区、配置、诊断六页。macOS 专属的运行控制、网络接入、导入和备份沿用相同视觉 token 与表单样式，不另建 HTML/CSS 业务界面。宿主只提供窗口、菜单、快捷键、文件面板与生命周期；导航和编辑状态归 React，Cmd+1 至 Cmd+6 切换页面，Cmd+R 刷新数据。宿主与资源加载机制见[界面宿主与资源加载](#界面宿主与资源加载)。

macOS 固定使用左侧图标导航、右侧内容区；侧栏在窗口缩窄时仍保留，不采用 LuCI 的顶部标签栏或移动底栏。内容区使用单一标题工具栏与分组行；配置分类是内容区内的次级导航，窄内容区可换行。桌面界面使用中性底色与主题强调色，绿色只表示健康或成功。应用图标和侧栏复用仓库 `assets/branding/opl-netfleet-logo.png`，不另画品牌标识。首次未配置、数据失效和请求进行中均明确呈现；读取失败保留已有内容供查看并阻止写入，不以模拟数据填充。表单刷新保留未保存草稿，切换页面不隐式提交。

窗口隐藏标题文字并使用全尺寸内容视图，侧栏顶部为窗口控制留出拖拽区；窗口背景与页面底色一致，页面自己绘制侧栏、工具栏和分组表面，不用系统材质覆盖业务配色，因此浅色界面在系统深色外观下仍保持同一套层级。宿主在文档开始时把当前系统强调色交给页面，页面据此派生强调色、浅底、边框和按钮前景；宿主不参与业务配色判断。

应用菜单的“代理”和菜单栏状态项由同一份页面投影重建，菜单栏状态项在不打开窗口时即可完成
日常操作：

- 首两行只读展示运行结论、当前出口与本地监听地址，停止时只显示“代理已停止”；
- “启动 NetFleet”“停止代理”按运行、已配置和忙碌状态启用，忙碌或状态未确认时交由页面解释原因；
- “出口”按每个启用的出口给出当前路径、本轮测量和健康结论，展开后是“自动选优”与后端确认可选的地区列表，当前项带选中标记；切换出口需要核心运行，未运行时这些项保持禁用；
- “网络接管”列出仅显式代理、系统代理与 TUN，标出当前方式；“运行模式”列出增强模式与原生配置，标出当前模式；
- “重新选优”“刷新状态”复用页面工具栏的同名动作。

菜单不携带业务状态，也不在 AppKit 侧重建启动、接管、选优或清理逻辑：页面每次读取或操作后用
命名消息上报运行、已配置、忙碌、模式、接入方式、地址、导出出口与地区；宿主按这份投影渲染菜单，
把用户选择作为命令发回页面，网络接管与运行模式仍走页面自己的确认框。页面未上报的项显示为不可用，
而不是在宿主侧推断。


### 订阅与流量接入

首次使用以添加订阅为主入口，下载、真实核心校验、地区发现和编译连续执行，核心保持停止。
来源名称可选，内部标识由本机生成。列表区分下载记录、配置纳入状态和运行测量；错误使用
可操作的中文提示，失败后重新读取真实状态并保留输入。后台刷新不反复禁用正在编辑的控件。

概览将代理核心与本机流量接入组合为紧凑控制区，原生配置模式置于按需打开的选项。订阅管理按需打开，文件备份位于配置，连接与日志按诊断分栏读取。
显式代理、系统代理和 TUN 是互斥选择；选择后仍需应用，系统接管另有确认。网络
组件安装、授权和接管生效分别按真实读回呈现，不以核心运行代替系统接管成功。

## 状态读取与平台回调

桌面页可见且未编辑、未执行操作时，每十秒读取一次快照；配置草稿不被刷新覆盖。
Node 串行业务请求，UCode 通过自身 socket 模块直接调用有限平台方法，不为每次回调启动
客户端进程；响应验证状态、长度与大小并设定超时。代码身份摘要由 Node 在本次私有代码
投影内计算，保留内核的有序双层 SHA-256 算法；不缓存执行身份、不放宽文件信任检查。回调不得再次
启动需获取同一网络锁的业务事务；订阅下载只保存原始元数据，配额解释在当前共享调用内完成。
旧缓存已保存的配额在真实刷新前保留；刷新后由共同解析器解释完整计数，缺失用量保持未知，
不把缺失字段当作零。隔离资格回执记录调用耗时，不把测试性能写入产品状态或选择规则。
