# 模块与扩展

NetFleet 的功能通过服务插件组合，其他语言实现通过进程插件接入。两者均安装到
`/usr/libexec/opl-netfleet/plugins/<id>/`，由微内核读取 `manifest.json` 发现，共用
CLI/RPC 与组件管理入口。新增插件无需修改静态注册表。

本文负责插件接入、进程协议与管理面投影；服务依赖、系统绑定、代码租约和资源交接的
唯一合同见[微内核与功能插件](microkernel.md)。开发步骤、示例和软件包工具见
[插件开发与安装](../development/plugins.md)。

## 分工

| 层次 | 责任 |
| --- | --- |
| 微内核 | 发现、接口版本、服务绑定、依赖解析、调用准入、作用域与代码生命周期 |
| 功能插件 | 产品模型、订阅、编译、选择、激活、恢复、管理、诊断、调度和界面，各自拥有状态与业务规则 |
| 后端与资源插件 | 所选后端的服务、DNS、透明代理、路由及其回读、排空与恢复 |
| 组件投影 | 安装记录、依赖、API 兼容性和插件管理入口 |
| LuCI / React 宿主 | 读取插件清单、组合导航、挂载页面并管理页面资源生命周期 |

插件通过公开服务读取或提交命令，不直接修改其他插件的私有状态。网络写操作继续经过
共享 mutation lock；服务组合不生成第二选择器、订阅 writer 或数据面 owner。Nikki 与
原生 Mihomo 是明确选择、互斥运行的后端。

## 服务插件接入

UCode 服务插件使用 `opl-netfleet-service-plugin.v1` 声明具名服务、接口 major、依赖、
命令与动作，也可以贡献配置和界面。模块返回接受 `context` 的工厂，使用 `context.use()` 取得已声明的服务，返回自身
接口对象。系统配置选择服务提供者，每次调用创建独立上下文并读取当前代码；未用到的
服务不执行代码。实例配置可以覆盖局部绑定与注入配置；作用域统一登记当前调用产生的
资源及其撤销函数。只贡献 UI 的插件不需要声明无用途的服务。

`load` 启用插件并为尚未绑定的服务设置提供者，不抢占已有绑定；`unload` 和 `reload`
通过包生命周期协调资源退出与恢复。纯服务无需自定义生命周期；持有长期资源的插件
声明成对 `drain/resume`，退出结果作为恢复输入。完整声明与行为由
[微内核合同](microkernel.md)维护。

## 进程插件协议

进程插件的目录包含 `manifest.json` 与可执行 `control`。声明使用
`opl-netfleet-plugin.v1`，记录 ID、名称、版本、API major、软件包、依赖、适用后端、
权限类别和自定义动作的读写分类。入口路径由安装布局确定，浏览器不能指定可执行文件
或 shell 命令。`control` 可使用设备已安装的任何语言运行时。

`backends` 为空数组表示后端无关，可在只安装微内核的系统中运行。非空数组声明所需
后端 ID，宿主通过系统配置的 environment 服务检查当前后端；缺少提供者或身份不符时
拒绝加载及业务动作，保留 get 和 unload。后端身份由功能插件提供，内核不限定后端种类。

每次调用启动当前 `control <action> <request-file>`，没有常驻代码缓存。请求是私有
JSON 文件，其中 `request` 对象包含 `api_version`、`id`、`action` 和 `params`；宿主
从标准输出读取 JSON 响应。成功响应返回 `ok: true` 与 `result` 对象，失败返回
`ok: false`。管理请求和响应各最多 64 KiB，单次执行最多 30 秒；标准错误不进入公开
响应，插件不得向标准输出混入日志。

`get/load/unload` 是稳定生命周期动作，`reload` 由宿主顺序执行 unload、回读、load、
回读。`get` 返回 `loaded` 与 `ready`；unload 先旁路、排空并清理自身资源，再返回
`loaded=false`。load 失败时宿主尝试 unload 并回读；无法确认退出时返回失败。只有
显式 load/reload 启用进程插件，安装本身不接管流量。

## 统一调用与权限

内核自带 `opl-netfleet.plugins` ubus 对象，提供 `plugins_list`、`plugin_read` 和
`plugin_call`，只安装内核也能发现和管理独立插件。默认产品的业务 RPC 由功能插件在
`opl-netfleet` 对象提供。两者复用相同的内核命令入口和读写准入。

`plugins-list` 只读取安装文件，不启动插件或执行探测。`plugin-read` 调用 get 或声明为
read 的动作；`plugin-call` 执行生命周期或声明为 write 的动作。写请求需要确认和插件
清单返回的 revision，宿主在共享 mutation lock 内重新读取身份并验证。revision 覆盖
插件目录中的全部文件，插件自己的业务状态 revision 通过 params 交给状态 owner 校验。
锁不传递给进程插件。

RPC 的 read/write ACL 分别授权，manifest 不能扩大现有权限。服务插件的 `commands`
绑定 CLI 名称，`actions` 绑定浏览器可调用的本插件服务方法，并声明 read 或 write。
统一动作入口验证声明、接口、代码 revision 和实例身份；新增业务动作无需增加静态
rpcd 方法。未声明的服务方法、包事务和内部资源交接不能经通用入口调用。

两种插件都可以用 `configuration` 引用自身已声明的配置读写动作，用 `ui` 贡献浏览器
页面；服务插件和进程插件分别由自身服务方法或 `control` 持有业务状态。清单投影动作、
配置、页面及实例身份；浏览器绑定本插件与当前实例调用，不接受模块路径或即时服务绑定。
页面发现、权限和缓存边界见[公开接口](interfaces.md#浏览器宿主与读取边界)，完整贡献合同
见[微内核](microkernel.md)。

插件以设备管理员权限运行，软件包来源必须受管理员信任。manifest 权限用于审阅和
接口准入，不是 OS 沙箱。固定安装目录及文件由 root 持有且不可由其他用户写入，拒绝
符号链接和越界路径。服务插件在调用上下文内实例化，进程插件通过独立进程执行。

## 组件与专用适配

组件页以插件详情作为统一管理入口，集中配置、真实状态与诊断；全局页面只保留索引或
跳转。组件投影读取安装记录、直接运行依赖、接口和后端兼容性，不从安装成功推断运行
健康，也不把虚拟包名当成实际包名查询。包管理器负责虚拟和传递依赖；直接安装记录中
没有同名包时，组件投影通过平台适配器查询依赖是否已被满足，不将缺少同名版本记录
误报为缺少依赖。

HTTPS 兼容由管理插件连接独立可选转换包。转换包的 `extension.json` 声明模块 ID 和
支持的 API major，软件版本来自安装记录。管理插件的“配置”进入业务配置页，“插件状态”
管理插件自身的加载与退出；管理插件停用时配置入口禁用，打开页面不隐式启用插件或转换包。
缺少或损坏声明、不支持的 API、缺少依赖及
不适用后端分别显示；读取组件清单不启动 Python、不加载私有 CA、不加入概览轮询。
不兼容时拒绝新增接管、配置应用与探测，`get` 和 `disable` 保留诊断与退出能力，仍由
该模块校验 revision、取得共享锁并完成旁路与排空。连接与设备信任的具体合同见
[HTTPS 兼容](https-compatibility.md)。

Dashboard 插件管理 Zashboard 入口和资源，面板资源可以独立更新；它仍通过所选后端
取得 controller 与运行态，不拥有持久策略或订阅。对应管理合同见
[设备独立管理](management.md)。

## 安装与热替换

自有与第三方插件使用标准 APK/IPK 和同一个
`/usr/libexec/opl-netfleet-plugin-package <id> <phase>` 包钩子入口。替换或删除代码前
等待在途调用退出，并按依赖关系排空受影响的资源插件；后置钩子完成恢复与维护标记清理。包管理器
不保证以钩子失败阻止替换，因此前置钩子在排空未确认时等待重试，不返回假成功。
维护期间拒绝对正在替换的插件执行普通调用，避免一次调用混用不同版本的字节。
代码租约、交接记录及恢复失败处理由[微内核合同](microkernel.md)定义。

服务插件升级保留系统启用状态与服务绑定，新调用使用新版；进程插件升级完成后显式
load。UI 资源使用绑定插件 revision 的目录，宿主发现升级或卸载后撤销旧页面并接入当前
贡献。插件私有数据迁移与回滚由自身实现。仅增加机场、地区或业务出口时修改 policy；
新增行为才需要插件。涉及文件系统、服务或数据面的部署遵守
[QEMU 与设备准入](overview.md#准入证据)，安装和开发步骤见
[插件开发与安装](../development/plugins.md)。
