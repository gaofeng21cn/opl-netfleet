# 模块与扩展

NetFleet 使用设备端的受限 Extension API v1 组合独立能力，不引入 Cordis、Node 宿主、
动态脚本加载或新的后台调度器。模块注册表只负责发现已编译接入的模块、检查接口和
投影组件信息；它不拥有 policy、订阅、测量、选择、证书或网络状态。

## 分工

| 层次 | 责任 | 不承担 |
| --- | --- | --- |
| 核心 | 编译、选优、证据、激活、恢复和共享 mutation lock | 可选增强的私有配置与协议处理 |
| 后端适配 | 唯一启用后端的服务、DNS、透明代理、路由与运行回读 | 第二套业务选择或跨后端双写 |
| 扩展模块 | 限定能力的配置、依赖、生命周期、诊断和局部恢复 | 改写其他模块状态或全局恢复路径 |
| 注册表 | 静态声明、动作路由、API 准入和组件投影 | 自建进程、锁、缓存、下载器或任意执行入口 |
| LuCI / React | 已有页面中的模块状态与受限命令 | 注册代码、解析私有配置、决定运行资格 |

HTTPS 兼容是独立可选软件包；Zashboard 是资源模块，其管理适配器随核心包交付，
面板资源仍独立更新。Nikki 和原生 Mihomo 是互斥后端，不是可同时开关的扩展。
故障恢复、编译和选择是不可卸载的核心职责，不能为了插件数量拆为独立运行 owner。

## Extension API v1

模块在其 application 适配器导出 `extension` 声明，包含 `id`、`label`、`api_version`、
`kind`、软件包、运行依赖、权限类别、UI 插槽与公开动作映射。动作映射只连接既有
CLI/RPC 名称、读写类别和模块内部方法。注册表只引用源码明确导入的适配器；不接受
浏览器上传 manifest，不从配置解析代码路径、shell 命令、URL 或回调。

`application/extensions.uc` 统一路由已注册动作，`main.uc` 不再逐项列出模块动作。
CLI 名称、rpcd 参数与 ACL 保持不变；声明不会自动扩大 RPC 权限。新增动作必须同时
实现适配器、明确 ACL，并通过声明与真实 RPC/CLI 的一致性验证。模块内部方法仍有
有限白名单，私有备份、tick、排空和引擎启动不能借注册表变成浏览器命令。

独立 HTTPS 包携带 `extension.json`，只声明模块 ID 和实现支持的 API major。
安装版本从 APK 安装记录取得，不用这个接口声明冒充软件版本。缺少或损坏声明、
不支持的 API、缺少运行依赖和不适用后端分别显示，不从安装成功推导运行健康。
依赖清单只投影具名的直接运行工具；虚拟包与传递库依赖由 APK 解析，不把虚拟依赖名
当作实际包名查询。没有安装记录的文件不能冒充已安装软件包。
模块信息复用组件页的一次安装记录读取；不启动 Python、不执行探针、不加载私有 CA，
也不加入常规概览轮询。

不兼容时拒绝新增接管、配置应用与探测。`get` 和 `disable` 是稳定的诊断与退出入口，
不因接口声明损坏被封锁；前者继续返回真实 revision，后者仍由原模块校验 revision、
获取共享锁并执行旁路与排空。关闭不能被注册表伪装成直接杀进程。模块不存在时 get
返回未安装，其余动作明确失败；基础 status、选优、恢复和其他模块仍可用。

接口准入只约束管理动作，不替代 gateway 的连接归属、内核租约或模块运行健康判定。
安装后保持关闭，启用仍需原有显式确认和目标验收。已建立连接不能因插件卸载、升级
或宿主退出而假称无损恢复；HTTPS 排空与故障旁路合同见[HTTPS 兼容](https-compatibility.md)。

## 扩展与交付

新增模块先证明真实独立 caller、状态、权限、失败影响和可恢复的生命周期，再加入
静态适配器注册。仅增加新的机场、地区或业务出口时修改 policy，不创建代码插件。
UI 以组件列表下的模块详情作为唯一管理入口，不为每个模块增加顶层页面。
模块详情集中配置、实际状态和诊断；全局页面只保留索引或跳转，不复制写入表单。

声明、路由、缺失与不兼容场景由源码合同验证；软件包必须携带适配器及接口声明。
涉及文件系统、服务或数据面部署时继续遵守[QEMU 与设备准入](overview.md#准入证据)。
运行依赖由 APK 管理；受限组件更新不会自动扩展成全系统升级或任意扩展热更新。
可选包升级与卸载继续经过自己的排空钩子，不复用核心包更新假设。

Cordis 可在未来真实需要进程内服务组合的管理端采用，但不能成为路由器联网前提。
动态插件市场、多后端通用框架和跨模块工作流不是此合同已实现的能力。
