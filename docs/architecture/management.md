# 配置与独立管理

本文定义配置文件、备份、核心维护及订阅接入的共同边界；网络设置字段、备份载体和系统
维护入口见 [OpenWrt](../platform/openwrt.md#网络配置与维护机制)与
[macOS](../platform/macos.md)。NetFleet 复用 Mihomo；核心具备某个功能不等于平台已完成
对应接管、清理和恢复验证。

## 网络接入

网络接入配置与业务 policy 分开，由平台 owner 提供真实可用字段、校验、执行和回读。
保存配置不等于网络生效；运行中应用需保留旧配置和运行选择，失败恢复。未知私有字段
必须保留，不能用有限表单重置完整配置，也不能跨 owner 暗中修改其他代理服务。

## 配置文件与维护

Profile 导入和编辑必须受控于自身私有存储，拒绝任意路径。JSON/YAML 输入先经结构化
转换及真实核心验证，再原子保存；使用中的配置须经完整应用事务或拒绝覆盖、删除。

备份包含声明配置、订阅来源、必要缓存、本地 Profile 及本平台支持的私有覆写；不包含
固件、整个系统配置、日志或进程状态。显式导出可包含秘密，不进入普通状态或浏览器缓存。
恢复先验证格式、路径白名单、大小、引用和运行身份；失败保留原配置，不能借恢复修改
其他服务或系统网络。插件代码不从备份执行或自动安装，平台声明是否支持插件组合备份。

核心启停、重载和恢复只调用所选运行 owner；诊断返回有界脱敏信息，控制接口故障时
仍能解释启动问题。完整后端面板与 NetFleet 的有限连接摘要分别展示。

## 配置来源与应用解释

配置读取区分声明值、合并后的配置值和正在运行的值；没有运行事实时显示未运行，
没有明确核心默认值时显示由核心决定。高级参数的覆盖与继承由配置 owner 解释，
表单和专家编辑共享同一草稿与事务，不分别持有配置。校验提供逐项变化，应用后
回读受影响参数，只有配置和运行结果一致才报告成功。平台定义可编辑参数与接管边界。
应用期间由原事务 owner 发布真实阶段及终态，界面可以收起进度并继续浏览。
请求连接中断只表示结果未确认；通过操作记录回读终态，不自动重新提交，也不提前报告成功。

## 规则与界面

本地业务规则使用域名后缀和 IPv4/IPv6 CIDR，目标为 capability 或直连，由共享校验器和
编译器生成有序规则；浏览器不解释规则匹配或生成运行配置。复杂上游格式留给受控 Profile。
页面归属和交互见[界面设计](../design/ui.md)，请求及权限见[公开接口](interfaces.md)。

## 订阅接入与策略归属

来源字段校验和订阅配额解释归共享订阅模型，地区发现、初始策略和增量合并归共享配置模型。
平台负责取得与校验候选内容、私有存储事务、调用编译以及返回保存和就绪结果，不自行修改
provider、地区映射或出口规则。新增来源只补充缺失资源，保留已有策略、未知字段、
Policy Source 与 Recovery Profile；未识别的来源可保存为待配置，不能冒充编译就绪。

来源集合变更按 provider 的 section 引用同步，不能假设业务 provider 标识等于来源标识。
删除仍被 Policy Source 或 Recovery Profile 引用的来源必须拒绝；已有策略至少保留一个
启用的 provider。候选计算不修改输入，平台在校验成功后原子提交。平台是否允许运行中
修改来源、如何应用新配置，见对应平台实现；共享模型不授予网络接管权限。
