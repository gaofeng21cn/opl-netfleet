# 设备地址来源

设备地址插件向已接入的消费者提供网卡身份与当前地址的对应关系。它不授予 HTTPS
解密权限，也不修改 DNS、路由或防火墙。`plugins/device-identity` 使用现有进程插件协议，
独立安装，默认关闭；当前消费者是 HTTPS 兼容的设备接入。

## 身份与来源

默认来源为 NetFleet 本机网络，UniFi 是可选来源，不是自动跟随的前提。
设备绑定由来源摘要和明确的网卡 MAC 组成；
摘要覆盖来源类型、接口或控制器地址、站点及 TLS 身份。更换来源后需要重新确认
设备接入；显示名、密码轮换和地址变化不改变设备绑定。

来源只能发布已确认的网卡身份和当前地址，不能从前缀、主机名、单个地址或流量相似性
推断设备身份。地址归属冲突、无法重新确认或来源失效时撤销旧授权证据；来源不修改
系统网络，也不授予消费者的信任权限。具体邻居发现、控制器认证与私有存储机制见
[OpenWrt 地址来源](../platform/openwrt.md#设备地址来源机制)。

## 更新与失效

`get` 返回配置摘要、配置 revision、来源绑定和最近同步状态；`configure` 原子保存
私有配置，其中 `enabled` 控制地址同步；`load/unload` 控制插件是否加载。
`ready` 表示插件接口可用，`source_ready` 表示来源证据尚未过期。`sync` 只刷新观察结果；`resolve` 只读
当前有效结果。两者通过已注册的 `plugin-read` 进入，配置动作经 `plugin-call`。
观察缓存不反向改写配置或消费者信任记录。

HTTPS 现有 tick 最多每三十秒触发一次有界异步同步；不建立新常驻循环。同步和
健康检查不共用网络等待，缓存最多有效一百二十秒，进程锁阻止重复同步。失败不延长
旧证据寿命；明确离线、地址移除或归属冲突立即从最新结果撤销。未知、过期和多设备
冲突的地址不交给消费者。同一来源重新出现健康证据后，后续连接可使用新地址。

地址来源在同步和配置变更时原子发布只读证据 `evidence.json`，与内部缓存分开；内容仅含
来源绑定、加载及启用状态、采样单调时钟和每个地址的到期时刻，不含凭据或会话。
HTTPS 健康轮次读取此发布文件，核验平台可信所有者、权限、大小、Schema 与到期时间，
不在每两秒轮次重新扫描插件和启动状态子进程。关闭、卸载或更换来源先删除已发布证据；
进程崩溃不能延长原证据寿命，缺失、无效和到期证据均旁路。管理 UI 仍通过正式插件入口
读取配置和同步状态。异步同步复用现有 tick，内核许可照常到期。
只读状态不加载控制器 HTTP 客户端或邻居探测线程模块；这些依赖仅在实际同步时加载。

卸载或关闭来源后，resolve 不返回有效地址。HTTPS 仍独立维护信任、规则和十秒
内核许可，已有连接继续排空；来源失效不关闭基础 NetFleet 或重启代理核心。

## 管理与验证

HTTPS 详情的“设备与信任”提供地址来源接入、启停、同步状态与设备绑定；组件列表
保留独立插件身份。未安装、未配置、认证失败、证书不符、数据不完整、过期与正常
同步分别呈现。已验证信任与当前存在可用地址分开显示。

验证覆盖真实 TLS 登录及客户端读取、证书不符时不发送凭据、IPv6 更换、地址归属
冲突、证据过期、关闭、配置并发，以及 HTTPS 消费者不因同步失败重启或重放请求。
平台交付与部署遵循对应资格和目标准入。
