# NetFleet 交付

从当前仓库读取事实，不复述旧任务的设备版本、SDK 路径或合格结论。用户已授权的目标
继续执行；此技能不添加确认步骤，不授权其他设备或全局网络变更。

先按本次请求选择路径。“更新到最新”默认是已配置、已签名且已获发布资格的 Feed 最新版。
源码领先或旧任务留有未发布功能，不自动把请求升级为开发、构建和发布；用户明确指定
未发布功能时才进入新版本交付。设备已满足本次请求且无故障证据时结束，不继续拓展任务。

先判断当前请求：

- **安装已发布插件**：读取 `AGENTS.local.md` 和
  `docs/operations/canary-promotion.md` 的有限插件组合更新段。使用现有
  `scripts/update-openwrt-plugins.py` Feed 入口；APK 求解依赖，不手配 HTTPS 包对。
  常规 Feed 更新省略 `--rollback-dir`，先用设备原事务保存的签名归档，确实缺失时才补外部包；
  同版本不代表相同归档，不能覆盖已有原始回退材料。
  复用本轮快照与有效签名索引；过期时走原组件检查入口刷新一次。正式更新器内含预览、
  事务与回读，不在外层重复全部检查。`no_change` 即结束；一次事务覆盖的依赖不再逐包执行。
  不为另一设备重新构建、运行 QEMU 或发布相同资产；浏览器登录不阻塞后台更新验收。
- **交付新版本**：读取 `docs/development/delivery.md` 的构建前预检与候选复用段，
  再按 `docs/development/validation.md` 选择资格。检查 `plugins/` 与设备载荷同步、
  实际变更包版本和目录投影后冻结 ref。使用构建入口 `--preflight`；macOS 不能直接
  运行 Linux SDK 宿主工具。发布时复用仓库 `scripts/openwrt-apk.py` 和同一 `NETFLEET_SDK`。
  先检查现有构建/资格进程和产物，不启动第二批重复任务。
- **流程耗时诊断**：读取构建 `<候选目录>.build-timings.json`、宿主更新回执 `timings`、设备
  `device_timings` 和事务 journal，找到最慢的实际阶段再改对应入口。缺少计时的历史
  结果不能补猜；构建、资格、下载、安装和观察分开报告。编译桶按 SDK 准备、清理、
  产品编译细分，日志只抽取 `time:` 行。已有成功计时不为报告再次构建；
  工具/SOP 优化不要求重装未变化产品或重跑未受影响的完整 QEMU。

源码检查、安装包、QEMU、实际设备、公开 Feed 各自只证明本层。复用资格遵循当前
仓库验证器，不改旧 receipt；当前默认包构建仍是整套候选，不宣称已实现全包内容寻址
增量构建。只改工具或文档时，不因 Git 提交变化重建未变化的已验证产品包。

设备执行沿用正式事务和 single-writer；超时先读 journal，不重放安装。生命周期可能
影响依赖该插件的服务，共享模型更新不能默认承诺 Mihomo PID 不变；普通页面或独立
服务更新则核对未受影响核心。保留用户开关和私有配置，插件失败只恢复对应资源。

结束时报告真实更新包、目标安装与运行回读、分段耗时、性能口径及未完成项。专业技能
只路由到上述唯一 SOP，不增加第二套安装器、设备清单、审批表或常驻监控。
